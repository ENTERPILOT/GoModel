A secret reference tells GoModel where to read a value instead of holding the
value itself:

```yaml
server:
  master_key: ${file:/run/secrets/gomodel-master-key}

providers:
  openai:
    type: openai
    api_key: ${env:OPENAI_KEY}
```

References work in any string setting of `config.yaml`, in the environment
variables that set those settings, and in provider environment variables:

```bash
OPENAI_API_KEY='${file:/run/secrets/openai}'
POSTGRES_URL='${file:/run/secrets/postgres-url}'
```

Single-quote the value in a shell so the shell does not expand it; `.env`
files need no quoting. Docker
Compose interpolates `${...}` in its own files, so write `$${file:...}` there;
Compose passes `${file:...}` on to GoModel.

## Syntax

A reference is `${<scheme>:<reference>}`. It may sit inside a larger value, and
one value may hold several:

```yaml
providers:
  openai:
    type: openai
    api_key: ${env:OPENAI_KEY}
    proxy_url: http://gomodel:${file:/run/secrets/proxy-pass}@proxy:3128

mcp:
  servers:
    github:
      url: https://mcp.example.com/mcp
      headers:
        Authorization: Bearer ${env:GITHUB_TOKEN}
```

The resolved value is used as-is. It may contain newlines, quotes, or any other
bytes, so a service-account JSON file works, and it is never scanned for
further references.

## Schemes

| Scheme | Reference | Value |
| --- | --- | --- |
| `env` | variable name | the variable's value; unset or empty stops startup |
| `file` | absolute path | the file's contents with one trailing newline removed; at most 1 MiB |

`file` reads Docker and Kubernetes secret mounts directly, so no entrypoint
script is needed to copy them into environment variables.

`env` differs from the plain `${NAME}` form in two ways: it is strict, and it
works in environment variables, not only in `config.yaml`. The plain form is
unchanged: `${NAME}` and `${NAME:-default}` are expanded in `config.yaml`, and
an unset `${NAME}` is left in place, which drops a provider whose key it is.

External secret managers (HashiCorp Vault, AWS Secrets Manager, GCP Secret
Manager, Azure Key Vault) plug in as further schemes with
[GoModel Pro](/pro/overview).

## Failures stop startup

A reference that cannot be resolved stops the gateway with an error naming the
setting and the scheme, never the value:

```text
failed to resolve secret references: providers.openai.api_key: secret reference ${file:...}: open /run/secrets/openai: no such file or directory
```

A failed [reload](/advanced/cli#configuration-reload) keeps the running
configuration. GoModel never starts with, or sends upstream, an unresolved
reference.

Only values in use are resolved: a provider value in `config.yaml` that an
environment variable overrides is not looked up.

## Rotation

GoModel does not poll `env` or `file` references. After rotating one, reload:
`gomodel --reload` or `SIGHUP`.

Extensions that watch a secret manager, such as GoModel Pro vaults, tell
GoModel when a value changes. GoModel then re-resolves every reference and:

- swaps provider API keys in place when only they changed. Requests in
  flight finish on the key they started with. Sessions pinned to a removed
  key move to another one; most other sessions keep their key.
- reloads the configuration, as `SIGHUP` does, when anything else changed
  (a DSN, the master key, a proxy URL, a service-account JSON). A failed
  reload keeps the running configuration and is retried on the next change.
- keeps every current value when a reference cannot be re-resolved, and logs
  a warning naming the setting.

The log line names the settings that changed, never their values:

```text
rotated provider API keys in place providers=[openai] fields=[providers.openai.api_keys[1]]
```

Changing the key of the provider used by the semantic cache embedder also
reloads, because the embedder keeps its own copy of the keys.

## Dashboard-managed credentials

Provider credentials, MCP server headers, and guardrail secret fields saved
from the dashboard or the admin API accept references too, in the same
syntax:

| Entity | Fields |
| --- | --- |
| Provider credentials | API keys, service-account JSON and base64 JSON, proxy URL |
| MCP servers | header values |
| Guardrails | the plugin's secret fields |

- The reference is stored as typed; GoModel resolves it when it builds the
  provider, MCP connection, or guardrail.
- A reference is not a secret, so the dashboard and the admin API show it
  unmasked. Literal secrets stay masked, and sending the mask back keeps the
  stored value.
- A reference that cannot be resolved is rejected on save with a `400` that
  names the field and the scheme.
- Each resolver call carries a field path for auditing, such as
  `provider_credentials.openai.api_keys[0]`,
  `mcp_servers.github.headers.Authorization`, or
  `guardrail_definitions.pii.config.api_key`.
- When a referenced value [rotates](#rotation), only the affected entity is
  reinstalled: a provider's keys are swapped in place, any other provider
  change rebuilds that provider, an MCP server is reconnected, and a guardrail
  is rebuilt. If the reference cannot be resolved, the entity keeps its
  current value.

Guardrail rules declared in `config.yaml` are stored the same way: a
reference in a plugin's secret field is saved as written and resolved when
the guardrail is built, so the database never holds the secret.

If a stored reference cannot be resolved at startup, the provider credential
or MCP server is logged and skipped, and the rest of the gateway starts.
Guardrails load as a set and fail closed: startup fails, a reload keeps the
running configuration, and a periodic refresh keeps the guardrails it has.

Values saved before references existed are read the same way, so a stored
literal containing `${scheme:...}` is now treated as a reference. Re-save it
with `$${` to keep it literal.

An extension can register a secret writer. A literal typed in the dashboard
is then stored in the secret manager and only the reference is saved, and the
writer's secrets are deleted when their entity or field is. Core GoModel ships
no writer.

## Literal `${`

Write `$${` for a literal `${`. `pa$${x}` becomes `pa${x}`.

## Limits

- `env` and `file` references are resolved when the configuration is loaded
  or reloaded; see [Rotation](#rotation).
- They apply to string settings. A boolean or number setting cannot be a
  reference.
- In dashboard-managed entities, only the fields listed in
  [Dashboard-managed credentials](#dashboard-managed-credentials) accept
  references.
