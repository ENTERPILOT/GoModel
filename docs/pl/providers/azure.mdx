Azure OpenAI posługuje się kształtem API OpenAI z dwiema różnicami, które obsługuje GoModel:
nagłówkiem `api-key` zamiast `Authorization: Bearer` oraz parametrem zapytania
`api-version` w URL-ach w zakresie deploymentu.

## Konfiguracja

```bash
AZURE_API_KEY=...
AZURE_BASE_URL=https://your-resource.openai.azure.com/openai/deployments/your-deployment
AZURE_API_VERSION=2024-10-21   # opcjonalne, domyślnie 2024-10-21
GOMODEL_MASTER_KEY=change-me
```

Albo w `config.yaml`:

```yaml
providers:
  azure:
    type: azure
    base_url: "${AZURE_BASE_URL}"
    api_key: "${AZURE_API_KEY}"
    api_version: "2024-10-21"
```

### Azure AI Foundry (API v1)

Endpointy Azure AI Foundry, takie jak
`https://proj1-resource.services.ai.azure.com/openai/v1/responses`, używają
niewersjonowanego API v1. Ustaw base URL na wszystko do `/openai/v1` włącznie:

```bash
AZURE_API_KEY=...
AZURE_BASE_URL=https://proj1-resource.services.ai.azure.com/openai/v1
```

Przy base URL-u `/openai/v1` GoModel domyślnie nie wysyła `api-version`, a
`model` w body requestu wybiera deployment, więc jeden provider obsługuje
wszystkie deploymenty zasobu. Nie ustawiaj `AZURE_API_VERSION` (ani
`api_version` w YAML-u powyżej); użyj `preview` tylko po to, żeby włączyć
funkcje preview. Klasyczne URL-e
`https://your-resource.openai.azure.com/openai/v1` działają tak samo.

`/openai/v1/models` zwraca modele zasobu, więc deployment nazwany tak jak jego
model (domyślnie w Foundry) jest routowany bez zmian. Własne nazwy deploymentów
podaj w `AZURE_MODELS` i ustaw `CONFIGURED_PROVIDER_MODELS_MODE=merge`.

## Weryfikacja

<CodeGroup>

```bash curl
curl -s http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [{"role": "user", "content": "Reply with the single word ok."}],
    "max_tokens": 80
  }'
```

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key=os.environ["GOMODEL_MASTER_KEY"],
)

completion = client.chat.completions.create(
    model="gpt-5",
    messages=[{"role": "user", "content": "Reply with the single word ok."}],
    max_tokens=80,
)

print(completion.choices[0].message.content)
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080/v1",
  apiKey: process.env.GOMODEL_MASTER_KEY,
});

const completion = await client.chat.completions.create({
  model: "gpt-5",
  messages: [{ role: "user", content: "Reply with the single word ok." }],
  max_tokens: 80,
});

console.log(completion.choices[0].message.content);
```

</CodeGroup>

`GET /v1/models` zwraca deploymenty udostępniane przez zasób Azure z
`owned_by: "azure"`. Streaming, Responses, embeddingi i batche działają
tak samo; batche są routowane przez ścieżkę zasobu `/openai/batches`
(`/openai/v1/batches` przy base URL-ach v1).

## Modele decyzyjne (Microsoft-Decision-1)

Wdróż `Microsoft-Decision-1` w tym samym zasobie Foundry, a GoModel udostępni go
na [`POST /v1/decisions`](/pl/advanced/decisions-api) (format OpenAI, z tłumaczeniem)
i [`POST /v1/systemone`](/pl/advanced/systemone-api) (przekazywany natywnie). Oba
trafiają do endpointu Foundry `/providers/microsoft/v1/systemone` pod głównym adresem
zasobu, niezależnie od postaci `AZURE_BASE_URL`.

Azure odrzuca nazwy deploymentów zawierające `Microsoft`, więc nazwij go na przykład
`ms-decision-1` i dodaj do listy, żeby GoModel mógł go routować:

```bash
AZURE_MODELS=ms-decision-1
CONFIGURED_PROVIDER_MODELS_MODE=merge
```

```bash
curl -s http://localhost:8080/v1/decisions \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "azure/ms-decision-1",
    "input": "The API returns 500 on every call.",
    "questions": [{
      "type": "choice",
      "name": "team",
      "instructions": "Which team should handle this ticket?",
      "choices": [
        {"value": "billing", "description": "Charges, invoices, and refunds"},
        {"value": "engineering", "description": "Bugs, errors, and outages"}
      ]
    }]
  }'
```

Microsoft-Decision-1 czyta tylko tekst i JSON: `/v1/decisions` odrzuca obrazy,
a `/v1/systemone` przekazuje requesty w wysłanej postaci, więc odpowiada na nie
Foundry. Nowe subskrypcje startują bez przydziału (quota) dla tego modelu,
więc przed wdrożeniem poproś o jego zwiększenie.

## Wiele deploymentów

Każdy deployment Azure to osobny endpoint. Zarejestruj je jako osobnych providerów
za pomocą zmiennych środowiskowych z sufiksem:

```bash
AZURE_GPT5_API_KEY=...
AZURE_GPT5_BASE_URL=https://your-resource.openai.azure.com/openai/deployments/gpt-5

AZURE_EMBED_API_KEY=...
AZURE_EMBED_BASE_URL=https://your-resource.openai.azure.com/openai/deployments/text-embedding-3-small
```

To rejestruje `azure-gpt5` i `azure-embed`. Żeby udostępnić wszystkie deploymenty
jednego zasobu przez jednego providera, użyj zamiast tego
[base URL-a v1](#azure-ai-foundry-api-v1).

## Uwagi

- GoModel akceptuje URL w zakresie deploymentu, który dostajesz z portalu. Dla
  operacji na poziomie konta (listowanie modeli, batche) GoModel automatycznie usuwa
  sufiks `/openai/deployments/<deployment>`, więc jeden
  `AZURE_BASE_URL` obsługuje zarówno czat, jak i wywołania na poziomie zasobu.
- `AZURE_API_VERSION` domyślnie wynosi `2024-10-21` dla URL-i w zakresie
  deploymentu i nie jest wysyłany dla URL-i v1. Ustaw go tylko wtedy, gdy
  potrzebujesz innej wersji stabilnej lub preview – na przykład nowszego Responses API.

## Rozwiązywanie problemów

- **`401 Unauthorized` / `403`** – `AZURE_API_KEY` nie pasuje do zasobu,
  na którym działa deployment, lub nazwa deploymentu w URL-u jest błędna.
- **`Resource not found` / `DeploymentNotFound`** – model w body requestu
  musi być nazwą deploymentu, a nie bazowego modelu.
- **`unsupported api version`** – podnieś `AZURE_API_VERSION` do wersji, którą
  obsługuje wywoływana funkcja. Nowsze funkcje Responses API wymagają najnowszych
  wersji preview. Przy base URL-ach v1 zostaw go pustym lub użyj `preview`.
- **`404` w Azure AI Foundry** – base URL musi kończyć się na `/openai/v1`, a nie
  na pełnym endpoincie (`/openai/v1/responses`) ani URL-u projektu
  (`/api/projects/...`).
