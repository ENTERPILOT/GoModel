Mistral AI (La Plateforme) jest obsługiwany pod adresem `https://api.mistral.ai/v1` w formacie
zgodnym z OpenAI. GoModel kieruje uzupełnienia czatu, listy modeli, embeddingi i żądania
passthrough przez współdzielony adapter OpenAI; punkt końcowy `/v1/responses` jest tłumaczony
przez uzupełnienia czatu. Pliki i zadania wsadowe nie są udostępniane dla tego dostawcy.

## Wyjście rozumowania (myślenia)

W modelach rozumujących (na przykład `mistral-large-latest`, `mistral-small-latest` oraz
hostowane modele rozumujące, takie jak Z.ai GLM) Mistral zwraca treść asystenta jako
**listę typowanych fragmentów** — fragment `thinking` ze śladem rozumowania i fragmenty `text`
z odpowiedzią — zarówno w odpowiedziach buforowanych, jak i w strumieniach SSE. Ten kształt nie
jest standardowym wyjściem czatu OpenAI i klienci tacy jak SillyTavern renderują go jako
krzaki.

Dostawca `mistral` w GoModel konwertuje go na standard automatycznie:

- fragmenty `thinking` są łączone w pole `reasoning_content`, a
- fragmenty `text` są łączone w zwykły ciąg `content`

— zarówno w odpowiedziach strumieniowych (`choices[].delta`), jak i buforowanych
(`choices[].message`). Nie wymaga to żadnej konfiguracji po stronie klienta.

Poziom rozumowania wyślij standardowym parametrem zagnieżdżonym; GoModel odwzorowuje go na
płaskie `reasoning_effort` Mistrala:

```json
{
  "model": "mistral-large-latest",
  "messages": [{ "role": "user", "content": "Ile to 17 * 23?" }],
  "reasoning": { "effort": "high" }
}
```

Wyliczenie całego API Mistrala to `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`,
a wartość jest przekazywana bez zmian. To, które poziomy akceptuje dany model, zależy od
modelu — przykładowo Mistral Large 4 przyjmuje `low`/`medium`/`high`, a hostowane modele GLM
`low`/`high`/`max` — więc nieobsługiwany poziom dla wybranego modelu odrzuca sam Mistral,
tak samo jak w przypadku natywnych SDK Mistrala.

Gdy klient odtwarza wcześniejszą turę asystenta, GoModel przed przekazaniem dalej usuwa jej
pole `reasoning_content`, ponieważ Mistral odrzuca ten nieznany człon błędem 422.

## Konfiguracja

```bash
MISTRAL_API_KEY=...
```

Albo w `config.yaml`:

```yaml
providers:
  mistral:
    type: mistral
    base_url: "https://api.mistral.ai/v1"
    api_key: "${MISTRAL_API_KEY}"
```

<Note>
  `type` dostawcy to `mistral`. Klucz konfiguracji (`mistral` w powyższym przykładzie) jest
  dowolny i służy tylko do identyfikacji tego wpisu w konfiguracji; można go zmienić.
</Note>

Można też nadpisać bazowy adres URL i listę modeli:

```bash
MISTRAL_BASE_URL=https://api.mistral.ai/v1
MISTRAL_MODELS=mistral-large-latest,mistral-small-latest,mistral-embed
```

<Note>
  Ustawienie `MISTRAL_MODELS` ogranicza w domyślnym trybie `allowlist` modele obsługiwane przez
  tego dostawcę do tej listy — żądania dotyczące innych modeli zwracają 404. Zobacz
  [Models modes](/advanced/config-yaml#models-modes) dla alternatyw `merge`/`fallback`.
</Note>

## Modele

Modele dostępne dla Twojego klucza API wyświetlisz przez `GET /v1/models`, albo wywołaj model
bezpośrednio przez zgodny z OpenAI punkt końcowy `/v1/chat/completions`:

```yaml
virtual_models:
  - source: mistral
    target: mistral/mistral-large-latest
```

## Embeddingi

Punkt końcowy Mistrala `/v1/embeddings` (na przykład `mistral-embed`) jest obsługiwany.
