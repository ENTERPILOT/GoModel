Ta strona opisuje Gemini z kluczami API **Google AI Studio**. Gemini w
Vertex AI w Google Cloud opisuje [przewodnik po Google Vertex AI](/pl/providers/vertex).

Domyślnie GoModel kieruje requesty Gemini dla czatu, Responses, embeddingów i
[obrazów](/pl/advanced/images-api) przez natywne API Gemini
(`generateContent`, `batchEmbedContents`, Imagen `predict`). Przełącz się na
endpoint kompatybilny z OpenAI, gdy potrzebujesz zachowania zgodności, którego natywny
adapter jeszcze nie implementuje (przede wszystkim zdalnych wartości `image_url`).

## Konfiguracja

```bash
GEMINI_API_KEY=...
GEMINI_API_MODE=native        # lub openai_compatible
```

Albo w `config.yaml`:

```yaml
providers:
  gemini:
    type: gemini
    api_key: "${GEMINI_API_KEY}"
    api_mode: native
```

<Note>
  `USE_GOOGLE_GEMINI_NATIVE_API` jest nadal respektowane jako przestarzały globalny przełącznik,
  gdy `GEMINI_API_MODE` dla danego providera nie jest ustawione. Wybieraj `GEMINI_API_MODE`.
</Note>

Natywny tryb AI Studio potrafi też materializować plany prompt cache, które GoModel tworzy po routingu,
jako pięciominutowe obiekty cached-content Gemini. Ponowne użycie jest ograniczone do klucza
API wybranego dla sesji; ruch bez sesji z rotującymi kluczami pomija
tworzenie obiektów, żeby zasób nigdy nie został użyty ponownie z niewłaściwymi danymi uwierzytelniającymi.
Modele Gemini 4 nie mają jawnego cache'owania (Google cache'uje wspólne prefiksy
niejawnie), więc nie tworzy się dla nich obiektów. Vertex obecnie otrzymuje
oryginalny request bez obiektów cached-content.

Google domyślnie przechowuje requesty do Gemini API w nowych projektach w płatnym
planie. W trybie natywnym `store: false` z Chat Completions jest przekazywane jako
rezygnacja per request w Gemini; endpoint kompatybilny z OpenAI nie ma takiego pola.

## Bazowe URL-e

GoModel utrzymuje osobne wewnętrzne adresy bazowe dla natywnego Gemini i
API kompatybilnego z OpenAI:

- natywny czat/modele: `https://generativelanguage.googleapis.com/v1beta`
- kompatybilny z OpenAI: `https://generativelanguage.googleapis.com/v1beta/openai`

`GEMINI_BASE_URL` je nadpisuje. Gdy wartość kończy się na `/openai`, GoModel
używa jej dla klienta kompatybilnego z OpenAI i wyznacza natywny adres bazowy przez
usunięcie `/openai`. Pliki i batche zawsze korzystają z interfejsu
kompatybilnego z OpenAI; czat, embeddingi i obrazy zależą od trybu API.

## Embeddingi

W trybie natywnym embeddingi są obsługiwane przez `models/{model}:batchEmbedContents`.
`dimensions` mapuje się na `outputDimensionality`, a `encoding_format: "base64"` jest
respektowane. Tryb natywny zapisuje użycie tokenów raportowane przez Gemini dla nowszych modeli,
takich jak `gemini-embedding-2`. Starsze modele, takie jak `gemini-embedding-001`, oraz interfejs
zgodny z OpenAI nie raportują użycia, więc te odpowiedzi zawierają zerowe liczby tokenów. Gdy model
jest wyceniany za token, takie wiersze użycia z zerową liczbą tokenów są oznaczane zastrzeżeniem
dotyczącym obliczenia kosztu.

## Generowanie i edycja obrazów

W trybie natywnym [endpointy obrazów kompatybilne z OpenAI](/pl/advanced/images-api)
działają z modelami obrazowymi Gemini (`gemini-2.5-flash-image`, `gemini-3.1-flash-image`,
`gemini-nano-banana-2.1`, ..., przez `generateContent`). Gdy model nie zwróci
obrazu, błąd zawiera finish reason i komunikat Gemini (na przykład
`IMAGE_RECITATION`). Google wycofał Imagen z API AI Studio w sierpniu
2026; Imagen jest nadal dostępny w [Vertex AI](/pl/providers/vertex). Edycja obrazów
wymaga trybu natywnego i modelu obrazowego Gemini; maski nie są obsługiwane. Szczegóły
mapowania parametrów i cen znajdziesz w [uwagach o providerze w Images API](/pl/advanced/images-api#google-gemini).

### Obrazy w odpowiedziach czatu

W trybie natywnym modele obsługujące obrazy (`gemini-2.5-flash-image`,
`gemini-3-pro-image-preview`, ...) mogą zwracać obrazy z Chat Completions i
Responses. `message.content` pozostaje ciągiem tekstowym. W Chat Completions
obrazy trafiają do osobnej tablicy `images` – tego samego pola, którego używa OpenRouter.
Klienci, którzy nie odczytują tego pola, po prostu je ignorują:

```json
"message": {
  "role": "assistant",
  "content": "Here is an image of a cat",
  "images": [{
    "type": "image_url",
    "image_url": {
      "url": "data:image/png;base64,iVBORw0...",
      "extra_content": {"google": {"thought_signature": "EvAC..."}}
    }
  }]
}
```

W Responses API każdy obraz jest osobnym elementem wyjścia `image_generation_call`.
Obraz w base64 znajduje się w `result`, a format w `output_format`, tak jak w
odpowiedziach OpenAI. Aby edytować obraz w kolejnej turze, odeślij wiadomość asystenta
(z `images`) lub element `image_generation_call` bez zmian, tak aby Gemini
otrzymał thought signature każdego obrazu. Klienci `/v1/messages` (Anthropic Messages API)
otrzymują tylko tekst. Odpowiedzi streamowane nie zawierają jeszcze wygenerowanych
obrazów.

Każdy obraz to kilka megabajtów base64. Logi audytowe przechwytują maksymalnie 1 MB
body odpowiedzi, więc zalogowane body jest obcinane i odpowiednio oznaczane. Cache
odpowiedzi przechowuje całą odpowiedź.

## Reasoning effort

W trybie natywnym `reasoning_effort` (lub `reasoning.effort`) jest tłumaczone na
`thinkingConfig` Gemini:

| Rodzina modeli | `none` / `minimal` | `low` / `medium` / `high` |
| ------------ | ------------------ | ------------------------- |
| Gemini 2.5 | `thinkingBudget` 0 / 1024 | `thinkingBudget` 1024 / 8192 / 24576 |
| Gemini 3 Flash, 3.5, 3.6 | `thinkingLevel: minimal` | `thinkingLevel` bez zmian |
| Gemini 3 Pro, 3.1 Pro, 3.7 Flash, 3.8 Flash, Gemini 4 | `thinkingLevel: low` | `thinkingLevel` bez zmian |

W Gemini 3 i 4 nie da się wyłączyć thinkingu, a modele Pro, 3.7 i 3.8
Flash oraz Gemini 4 (`gemini-4-argon`, ...) odrzucają `minimal`, więc GoModel wysyła
najniższy poziom akceptowany przez te modele, zamiast zwracać błąd 400 od Google. Jawne
`extra_body.google.thinking_config` jest przekazywane bez zmian, gdy ustawia
`thinking_budget` lub `thinking_level`; w przeciwnym razie `reasoning_effort` dodaje
do niego swój poziom lub budżet. To samo ograniczanie obowiązuje w trybie `openai_compatible`, w którym endpoint Google
przekazuje `reasoning_effort` jako poziom thinkingu i odrzuca te same wartości.

W Gemini 4 tokeny thinkingu wliczają się do `max_tokens`, a długa odpowiedź, która
osiągnie limit wyjścia per request, kończy się z `length` (`CONTINUATION` w Gemini);
GoModel jej nie wznawia.

## Parametry samplingu w Gemini 3 i 4

Przewodniki migracji Google do Gemini 3 i 4 zalecają usunięcie `temperature`, `top_p`
i `top_k` z każdego requestu, bo modele są dostrojone pod swoje wartości domyślne
(Gemini 4 je ignoruje), i wymieniają `candidate_count` jako nieobsługiwane. W trybie
natywnym GoModel pomija więc te cztery pola dla Gemini 3 i nowszych
(`gemini-3-*`, `gemini-3.8-*`, `gemini-4-*`, ...), a nadal przekazuje je dla
Gemini 2.5, Gemmy i innych modeli. `presence_penalty` i `frequency_penalty`
nigdy nie są przekazywane: każdy aktualny model Gemini API, łącznie z 2.5, odpowiada
HTTP 400 "Penalty is not enabled for this model". Nie dotyczy to `max_tokens`, `stop`,
`response_format` ani ustawień thinkingu.

W trybie `openai_compatible` GoModel pomija też pola, które endpoint Google
odrzuca jako nieznane (`seed`, `logprobs`, `top_logprobs`, `store`, `metadata`,
`logit_bias`, `top_k`, `prediction`, `prompt_cache_key`, `safety_identifier`,
`verbosity`, `web_search_options`) wraz z karami, oraz naprawia streamowane
wywołania narzędzi, które ten endpoint emituje bez `index` i kończy z
`stop` zamiast `tool_calls`.

## Thought signatures

Gemini 3 i 4 dołączają zaszyfrowane `thoughtSignature` do emitowanych wywołań funkcji
i odrzucają kolejny request (HTTP 400, "Function call is missing a
thought_signature"), gdy to wywołanie wraca w historii bez sygnatury. W
trybie natywnym GoModel udostępnia sygnaturę tak samo jak własny endpoint Google
kompatybilny z OpenAI, więc klient, który odsyła wiadomości asystenta
bez zmian, nadal działa:

```json
{
  "role": "assistant",
  "tool_calls": [{
    "id": "call_1",
    "type": "function",
    "function": {"name": "lookup_weather", "arguments": "{\"city\":\"Warsaw\"}"},
    "extra_content": {"google": {"thought_signature": "EvACCu0CARFNMg..."}}
  }]
}
```

To samo pole `extra_content` pojawia się w streamowanych deltach `tool_calls`, w
elementach output `function_call` w Responses API, w blokach `tool_use` w Anthropic Messages API
oraz (dla tur wyłącznie tekstowych) w samej wiadomości asystenta.
Odsyłaj je dosłownie; tylko pierwsze wywołanie w równoległej grupie ma
sygnaturę. Inni providerzy nigdy jej nie widzą; wspólną konwencję opisuje strona
[Extra content, bloki thinking i thought signatures](/pl/advanced/extra-content). Akceptowane jest też płaskie `thought_signature` (lub
`thoughtSignature`) w wywołaniu narzędzia lub w jego obiekcie `function`,
więc klienci zbudowani pod inne gatewaye nadal działają.

Gdy historia Gemini 3 lub 4 zawiera wywołanie funkcji bez żadnej sygnatury (rozmowa
zaczęła się na innym modelu lub klient pominął to pole),
GoModel wysyła udokumentowany przez Google placeholder `skip_thought_signature_validator`,
zamiast zwracać błąd 400 – tak samo w trybie natywnym, jak i `openai_compatible`.
Ciągłość reasoningu jest dla tej tury ograniczona, więc lepiej odsyłać prawdziwą
sygnaturę.

## Obrazy na wejściu

| Tryb | `image_url` w stylu OpenAI |
| ---- | ----- |
| `native` (domyślnie) | tylko osadzone URL-e `data:` – zdalne URL-e `https://...` są odrzucane |
| `openai_compatible` | zdalne URL-e w stylu OpenAI są przekazywane do endpointu Google kompatybilnego z OpenAI |

W przypadku obrazów hostowanych pod URL-em w trybie natywnym własne przykłady Google najpierw pobierają URL,
a następnie wysyłają bajty do `generateContent`.

## Wideo na wejściu

| Tryb | `video_url` w stylu OpenAI |
| ---- | ----- |
| `native` (domyślnie) | osadzone URL-e `data:`, linki YouTube, URI z Gemini Files API i obiekty `gs://` |
| `openai_compatible` | przekazywane bez zmian, ale endpoint Google kompatybilny z OpenAI nie obsługuje wideo na wejściu – użyj `native` |

```json
{"type":"video_url","video_url":{"url":"https://www.youtube.com/watch?v=abc123"}}
```

W trybie natywnym URL `data:` staje się osadzoną częścią wideo (domyślnie
`video/mp4`, gdy data URL nie deklaruje typu mediów), a URI YouTube, Files API
i Cloud Storage są wysyłane jako referencja do pliku, którą Gemini rozwiązuje samodzielnie. Każdy
inny zdalny URL `https://...` jest odrzucany, a nie pomijany – najpierw prześlij plik
przez Gemini Files API.

## Wiadomości i narzędzia

W trybie natywnym pola czatu OpenAI mapują się na `generateContent` w następujący sposób:

| Pole OpenAI | Gemini `generateContent` |
| ------------ | ------------------------ |
| wiadomości `system` i `developer` | `system_instruction` (Gemini nie ma osobnej roli developer) |
| `tool_choice: "auto"` / `"required"` / `"none"` | `functionCallingConfig.mode` `AUTO` / `ANY` / `NONE` |
| `tool_choice` wskazujące jedną funkcję | `ANY` z `allowedFunctionNames: [name]` |
| `tool_choice: {"type": "allowed_tools", ...}` z trybem `required` | `ANY` z `allowedFunctionNames` |
| `tool_choice: {"type": "allowed_tools", ...}` z trybem `auto` | `VALIDATED` z `allowedFunctionNames` |
| `strict: true` w dowolnym narzędziu funkcyjnym | `VALIDATED` zamiast `AUTO`; `ANY` już wymusza schemat |
| `parallel_tool_calls: false` | pomijane; Gemini nie ma odpowiednika |

Gemini akceptuje `allowedFunctionNames` tylko z `ANY` lub `VALIDATED`, dlatego
podzbiór `auto` staje się `VALIDATED`: model nadal może odpowiedzieć tekstem,
ale każde wykonane przez niego wywołanie jest ograniczone do wymienionych narzędzi. `VALIDATED` dotyczy
całego requestu, więc jedno narzędzie strict sprawia, że każde zadeklarowane narzędzie
jest walidowane względem schematu.

Gemini nie pozwala ograniczyć tury do jednego wywołania funkcji, a wskazanie pojedynczego
narzędzia nie pomaga: Gemini może wywołać tę samą funkcję więcej niż raz w jednej turze.
Gdy `parallel_tool_calls: false` (lub `disable_parallel_tool_use` z Anthropic)
ma znaczenie, obsłuż lub odrzuć dodatkowe wywołania w swoim kliencie.

Wybór `allowed_tools` z pustą listą `tools` jest odrzucany z kodem 400, tak jak
robi to OpenAI.

## Jeszcze niezintegrowane

- Automatyczne pobieranie zdalnych wartości `image_url` w trybie natywnym.
- Przesyłanie zdalnych obrazów lub wideo przez Gemini Files API przed requestem czatu.
