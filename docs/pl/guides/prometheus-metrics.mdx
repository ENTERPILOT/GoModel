<Warning>
  Obsługa Prometheusa jest **eksperymentalna**. Nazwy metryk, etykiety i
  opcje konfiguracji mogą się zmienić bez uprzedzenia. Jeśli zależy Ci na
  stabilnym schemacie, przypnij konkretną wersję GoModel.
</Warning>

Ten przewodnik wyjaśnia, jak skonfigurować eksperymentalny endpoint metryk
Prometheus w GoModel.

## Szybki start

### Domyślnie wyłączone

Metryki są **domyślnie wyłączone**. Aby włączyć zbieranie metryk, ustaw
`METRICS_ENABLED=true` i uruchom GoModel:

<CodeGroup>

```bash Docker (plik .env)
# Dodaj METRICS_ENABLED=true do pliku .env, a następnie:
docker run --rm -p 8080:8080 --env-file .env enterpilot/gomodel
# Metryki dostępne pod http://localhost:8080/metrics
```

```bash Docker (inline -e)
docker run --rm -p 8080:8080 \
  -e METRICS_ENABLED=true \
  enterpilot/gomodel
# Metryki dostępne pod http://localhost:8080/metrics
```

```bash Binary (make build)
# Wymaga Go 1.27.4+; tworzy bin/gomodel.
make build

export METRICS_ENABLED=true
./bin/gomodel
# Metryki dostępne pod http://localhost:8080/metrics
```

</CodeGroup>

<Note>
  W dalszej części przewodnika pokazujemy tylko ustawianą zmienną. Zastosuj ją
  w sposób odpowiadający wybranemu wyżej sposobowi uruchamiania – `.env` z
  `--env-file`, flaga `-e` w linii poleceń albo `export` przed `./bin/gomodel` –
  i zrestartuj GoModel.
</Note>

### Wyłączanie metryk

**Opcja 1: zmienna środowiskowa**

```bash
METRICS_ENABLED=false
```

**Opcja 2: plik .env**

```bash
echo "METRICS_ENABLED=false" >> .env
```

**Opcja 3: config.yaml**

```yaml
metrics:
  enabled: false
```

### Własny endpoint metryk

Zmień domyślną ścieżkę `/metrics`:

```bash
METRICS_ENABLED=true
METRICS_ENDPOINT=/internal/prometheus
```

## Opcje konfiguracji

### Przez zmienne środowiskowe

| Zmienna                          | Wartość domyślna | Opis                                                        |
| -------------------------------- | ---------------- | ----------------------------------------------------------- |
| `METRICS_ENABLED`                | `false`          | Włącza/wyłącza zbieranie metryk                             |
| `METRICS_ENDPOINT`               | `/metrics`       | Ścieżka HTTP endpointu metryk                               |
| `METRICS_CALLER_USER_PATH`       | `false`          | Dodaje user path do [metryk wywołującego](#wymiary-wywołującego) |
| `METRICS_CALLER_USER_PATH_DEPTH` | `2`              | Liczba początkowych segmentów user path, które są zachowywane |
| `METRICS_CALLER_AUTH_KEY`        | `false`          | Dodaje nazwę zarządzanego klucza API                        |
| `METRICS_CALLER_REQUEST_LABELS`  | `false`          | Dodaje etykiety requestu                                    |
| `METRICS_CALLER_MAX_VALUES`      | `100`            | Liczba różnych wartości zachowywanych dla każdego wymiaru   |

### Przez config.yaml

```yaml
metrics:
  # Włącza lub wyłącza zbieranie metryk Prometheus
  # Gdy wyłączone, żadne metryki nie są zbierane, a endpoint zwraca 404
  enabled: true

  # Ścieżka endpointu HTTP, pod którą udostępniane są metryki
  endpoint: "/metrics"

  # Kto wysłał request: wymiary na metrykach tokenów, kosztów i requestów
  # per wywołujący. Domyślnie wszystko wyłączone; zobacz „Wymiary
  # wywołującego" poniżej.
  caller_dimensions:
    user_path: false
    user_path_depth: 2
    auth_key: false
    request_labels: false
    max_values: 100
```

## Przykłady

### Konfiguracja produkcyjna (metryki włączone)

**.env**

```bash
PORT=8080
GOMODEL_MASTER_KEY=your-secret-key
METRICS_ENABLED=true
METRICS_ENDPOINT=/metrics
OPENAI_API_KEY=sk-...
```

### Konfiguracja deweloperska (metryki wyłączone)

**.env**

```bash
PORT=8080
METRICS_ENABLED=false
OPENAI_API_KEY=sk-...
```

### Własny endpoint do wewnętrznego monitoringu

**config.yaml**

```yaml
server:
  port: "8080"
  master_key: "${GOMODEL_MASTER_KEY}"

metrics:
  enabled: true
  endpoint: "/internal/prometheus" # Własna ścieżka

providers:
  openai:
    type: "openai"
    api_key: "${OPENAI_API_KEY}"
```

```json
{ "level": "INFO", "msg": "prometheus metrics enabled", "endpoint": "/metrics" }
```

### Przetestuj endpoint metryk

**Gdy włączone:**

<CodeGroup>

```bash curl
curl http://localhost:8080/metrics
# Zwraca metryki Prometheus w formacie tekstowym
```

```python Python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080", api_key="unused")
metrics = client.get("/metrics", cast_to=str)

print(metrics)
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: "unused",
});

const metrics = await client.get("/metrics");
console.log(metrics);
```

</CodeGroup>

**Gdy wyłączone:**

<CodeGroup>

```bash curl
curl http://localhost:8080/metrics
# Zwraca 404 Not Found
```

```python Python
from openai import NotFoundError, OpenAI

client = OpenAI(base_url="http://localhost:8080", api_key="unused")

try:
    client.get("/metrics", cast_to=str)
except NotFoundError as error:
    print(error.status_code)  # 404
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: "unused",
});

try {
  await client.get("/metrics");
} catch (error) {
  console.log(error.status); // 404
}
```

</CodeGroup>

## Wpływ na wydajność

### Metryki włączone

- Minimalny narzut: ok. 100 ns na request na wykonanie hooków
- Pamięć: ok. 1 MB na przechowywanie metryk (zależy od kardynalności)
- CPU: pomijalny wpływ (`<0.1%` w benchmarkach)

### Metryki wyłączone

- **Zerowy narzut**: brak zarejestrowanych hooków i brak zbierania danych
- Biblioteka metryk jest nadal linkowana, ale nieaktywna
- Zalecane dla maksymalnej wydajności w środowiskach nieprodukcyjnych

## Kwestie bezpieczeństwa

### Udostępnianie endpointu metryk

Endpoint `/metrics` jest chroniony uwierzytelnianiem master key, gdy master key
jest skonfigurowany – tak samo jak inne endpointy HTTP. Jeśli master key nie jest
skonfigurowany, endpoint jest dostępny bez uwierzytelniania, co pozwala
Prometheusowi scrapować metryki bez danych uwierzytelniających.

Jeśli potrzebujesz dodatkowo zabezpieczyć endpoint metryk:

1. **Użyj własnej, wewnętrznej ścieżki:**

   ```yaml
   metrics:
     endpoint: "/internal/prometheus" # Trudniejsza do odgadnięcia
   ```

2. **Użyj zabezpieczeń na poziomie sieci:**
   - Skonfiguruj reguły firewalla tak, aby dopuszczały tylko serwer Prometheus
   - Używaj prywatnej sieci do zbierania metryk
   - Wdróż Prometheusa w tym samym VPC/tej samej sieci

3. **Reverse proxy z uwierzytelnianiem:**

   ```nginx
   location /metrics {
       auth_basic "Metrics";
       auth_basic_user_file /etc/nginx/.htpasswd;
       proxy_pass http://gomodel:8080/metrics;
   }
   ```

## Alerty na puste odpowiedzi

Provider czasem odpowiada `200`, ale nie zwraca żadnych choices, żadnego
outputu ani użycia tokenów. `gomodel_requests_total` liczy takie wywołania jako
udane, dlatego GoModel dodatkowo zwiększa `gomodel_empty_responses_total` i
loguje ostrzeżenie (`provider returned 200 with an empty response`).

| Etykieta   | Wartości                                  |
| ---------- | ----------------------------------------- |
| `provider` | Nazwa providera z Twojej konfiguracji     |
| `model`    | Model wysłany do upstreamu                |
| `reason`   | `no_choices`, `no_output` lub `no_usage`  |

Chat completion bez choices zwraca też klientowi `502` albo przechodzi przez
failover, jeśli istnieje cel failoveru. Odpowiedź z treścią, ale bez użycia, jest
nadal zwracana; psuje tylko śledzenie użycia i kosztów.

```promql
sum(rate(gomodel_empty_responses_total[5m])) by (provider, model, reason) > 0
```

## Alerty na utracone użycie

Użycie jest zapisywane w magazynie partiami. Wpisu, który nigdy nie trafi do magazynu,
brakuje w widokach użycia, [budżetach](/pl/features/budgets) i fakturach, więc GoModel
liczy go w `gomodel_usage_entries_dropped_total` i loguje.

| Etykieta | Wartości                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `reason` | `buffer_full` (osiągnięto `USAGE_BUFFER_SIZE`), `write_failed` (zapis partii zwrócił błąd) lub `logger_closed` (zobacz poniżej) |

Przy `buffer_full` zwiększ `USAGE_BUFFER_SIZE`. Przy `write_failed` błąd zapisu znajdziesz
w logu serwera. `logger_closed` liczy użycie zarejestrowane po zamknięciu loggera użycia,
na przykład przez request lub sesję wciąż trwające w chwili zamykania;
proces może się zakończyć, zanim Prometheus odczyta licznik, więc stratę zapisuje log.

```promql
sum(increase(gomodel_usage_entries_dropped_total[5m])) by (reason) > 0
```

## Metryki tokenów i kosztów

GoModel zlicza tokeny i koszt każdego requestu, dla którego zapisuje użycie,
więc możesz rysować wykresy wydatków i ustawiać na nie alerty bez odpytywania
bazy użycia. Liczniki są aktualizowane po zakończeniu odpowiedzi; request
streamowany jest liczony raz, w chwili zamknięcia streamu.

| Metryka                           | Zlicza                                                        |
| --------------------------------- | ------------------------------------------------------------- |
| `gomodel_tokens_total`            | Tokeny wysłane do providerów i przez nich zwrócone            |
| `gomodel_token_details_total`     | Tokeny z cache, zapisy do cache i tokeny reasoningu           |
| `gomodel_provider_cost_usd_total` | Ile naliczają providerzy, w USD                               |
| `gomodel_billed_cost_usd_total`   | Ile naliczono wywołującym, w USD (koszt providera plus narzut) |

Wszystkie cztery mają etykiety `provider` (nazwa providera z konfiguracji)
i `model` (model, który odpowiedział) oraz
[etykiety wywołującego](#wymiary-wywołującego). Dwie metryki tokenów mają
dodatkowo `token_type`:

| Metryka                       | `token_type`        | Znaczenie                                                  |
| ----------------------------- | ------------------- | ---------------------------------------------------------- |
| `gomodel_tokens_total`        | `input`             | Wszystkie tokeny promptu: bez cache, z cache i zapisy do cache |
| `gomodel_tokens_total`        | `output`            | Wszystkie tokeny odpowiedzi, łącznie z reasoningiem        |
| `gomodel_token_details_total` | `input_cached`      | Tokeny promptu odczytane przez providera z jego prompt cache |
| `gomodel_token_details_total` | `input_cache_write` | Tokeny promptu zapisane przez providera do jego prompt cache |
| `gomodel_token_details_total` | `output_reasoning`  | Tokeny reasoningu („thinking")                             |

Szczegóły są **częściami** `gomodel_tokens_total`, a nie dodatkiem do niej,
i dlatego są osobną metryką: `sum(gomodel_tokens_total)` to suma tokenów,
a żadna suma po jednej metryce nie liczy tokenu dwa razy. To samo dotyczy
obu metryk kosztów. Providerzy różnie raportują tokeny z cache i tokeny
reasoningu (Anthropic podaje odczyty z cache ponad input, xAI podaje
reasoning ponad output); GoModel je normalizuje, więc `input` i `output`
znaczą to samo dla każdego providera.

```promql
# Tokeny na minutę według modelu i kierunku
sum(rate(gomodel_tokens_total[5m])) by (model, token_type) * 60

# Udział tokenów promptu obsłużonych z prompt cache providera
sum(rate(gomodel_token_details_total{token_type="input_cached"}[5m]))
  / sum(rate(gomodel_tokens_total{token_type="input"}[5m]))

# Wydatki u providerów na godzinę według providera
sum(increase(gomodel_provider_cost_usd_total[1h])) by (provider)
```

Co jest liczone, a co nie:

- **Śledzenie użycia musi być włączone** (`USAGE_ENABLED=true`, wartość
  domyślna). Metryki powstają z tych samych wpisów, które pokazuje dashboard
  użycia.
- **Koszt wymaga cennika.** Request do modelu bez znanej ceny dodaje tokeny,
  ale nie koszt. `gomodel_billed_cost_usd_total` jest zapisywana tylko wtedy,
  gdy włączone są [narzuty cenowe](/pl/features/cost-tracking).
- **Trafienia w cache odpowiedzi** nigdy nie docierają do providera, więc nie
  dodają tokenów ani kosztu providera. Naliczone trafienie w cache
  (`pricing.bill_cache_hits`) nadal trafia do `gomodel_billed_cost_usd_total`.
- **Wywołania narzędzi MCP** nie zapisują tokenów ani kosztu, więc niczego nie
  dodają.
- Seria pojawia się, gdy ma wartość różną od zera.

## Wymiary wywołującego

Domyślnie metryki nie mówią nic o tym, kto wysłał request. Dodają to trzy
opcjonalne wymiary:

| Ustawienie                      | Etykieta         | Wartość                                                              |
| ------------------------------- | ---------------- | -------------------------------------------------------------------- |
| `METRICS_CALLER_USER_PATH`      | `user_path`      | [User path](/pl/features/user-path), przycięty do `METRICS_CALLER_USER_PATH_DEPTH` segmentów; `/` dla requestu bez user path |
| `METRICS_CALLER_AUTH_KEY`       | `auth_key`       | Nazwa zarządzanego klucza API. Pusta dla klucza master               |
| `METRICS_CALLER_REQUEST_LABELS` | `request_labels` | Etykiety requestu, posortowane i rozdzielone przecinkami (`prod,team-a`). Przecinek wewnątrz etykiety jest zapisywany jako `%2C`, a znak procentu jako `%25` |

```bash
METRICS_ENABLED=true
METRICS_CALLER_AUTH_KEY=true
```

```promql
# Tokeny na minutę według klucza API
sum(rate(gomodel_tokens_total[5m])) by (auth_key) * 60

# Odsetek błędów według klucza API
sum(rate(gomodel_caller_requests_total{status_type="error"}[5m])) by (auth_key)
  / sum(rate(gomodel_caller_requests_total[5m])) by (auth_key)

# Naliczony koszt z ostatnich 24 godzin dla etykiety zespołu, niezależnie od innych etykiet requestu
sum(increase(gomodel_billed_cost_usd_total{request_labels=~"(.*,)?team-a(,.*)?"}[24h]))
```

Etykiety są na czterech metrykach tokenów i kosztów oraz na
`gomodel_caller_requests_total`, liczniku requestów z etykietami `provider`,
`model` i `status_type`, który istnieje tylko wtedy, gdy włączony jest
któryś wymiar wywołującego. **Nie** są dodawane do `gomodel_requests_total`,
histogramu `gomodel_request_duration_seconds` ani wskaźnika requestów
w toku: każda wartość wywołującego mnożyłaby każdą z ich serii, a histogram
ma jedną serię na bucket.

Wymiar wyłączony albo bez wartości dla danego requestu jest eksportowany jako
pusta etykieta, którą Prometheus traktuje jak brak etykiety. Włączony user
path zawsze ma wartość: request bez user path jest raportowany jako `/`.
Sekret i ID klucza API nigdy nie są eksportowane; klucz, który już nie
istnieje, jest raportowany jako `{unknown}`.

### Ograniczanie kardynalności

Każdy włączony wymiar mnoży liczbę serii, więc włączaj tylko to, o co pytasz
w zapytaniach.

- **Głębokość user path.** Przy domyślnej głębokości 2 ścieżka
  `/team/alice/laptop` jest raportowana jako `/team/alice`. Zmniejsz ją, żeby
  grupować mocniej; zwiększaj tylko wtedy, gdy głębsze poziomy mają mało
  wartości.
- **Limit wartości.** Każdy wymiar zachowuje pierwsze
  `METRICS_CALLER_MAX_VALUES` (domyślnie 100) różnych wartości, które zobaczy.
  Limit dotyczy każdego wymiaru osobno: przy trzech włączonych wymiarach
  zachowanych może być do 300 wartości. Kolejne wartości dzielą jedną serię:
  `{other}` (`/{other}` dla user path). Przyjęte wartości zachowują własną
  serię do restartu GoModel.
- **Odrzucane wartości.** Wartość dłuższa niż 256 bajtów, niebędąca
  poprawnym UTF-8 albo zapisana jak nazwa zarezerwowana (`{other}`,
  `/{other}`, `{unknown}`) jest raportowana jako `{other}` (`/{other}` dla
  user path) i nie zajmuje miejsca w limicie.
- **Etykiety requestu to jedna wartość na zestaw etykiet.** `prod,team-a`
  i `team-a` to różne wartości, więc zestawy etykiet wyczerpują limit dużo
  szybciej niż same etykiety: klient, który dowolnie łączy 7 etykiet, może
  wysłać 127 różnych zestawów, czyli sam zapełnić domyślny limit. Każdy
  kolejny zestaw, poprawny czy nie, jest potem raportowany jako `{other}` aż
  do restartu GoModel. Jeśli klienci wysyłają dowolne etykiety, zostaw ten
  wymiar wyłączony.
- **Najgorszy przypadek.** Każdy wymiar daje co najwyżej swój limit plus
  `{other}` i pustą wartość (dla kluczy API także `{unknown}`). Przy trzech
  wymiarach i domyślnym limicie jeden provider i model mogą osiągnąć
  102 × 103 × 102 ≈ 1,07 mln serii na typ tokenów. Eksportowane są tylko
  kombinacje, które faktycznie wystąpią, ale włączaj wymiary pojedynczo
  i obniż `METRICS_CALLER_MAX_VALUES` do spodziewanej liczby wartości.

**prometheus.yml**

```yaml
scrape_configs:
  - job_name: "gomodel"
    static_configs:
      - targets: ["localhost:8080"]
    metrics_path: "/metrics" # Lub Twoja własna ścieżka
    scrape_interval: 15s
    scrape_timeout: 10s
```

```yaml
scrape_configs:

    scrape_interval: 15s
```

## Rozwiązywanie problemów

### Endpoint metryk zwraca 404

**Przyczyna:** metryki są wyłączone (wartość domyślna).

**Rozwiązanie:**

```bash
# Sprawdź konfigurację
echo $METRICS_ENABLED  # "true" włącza; pusta wartość lub "false" wyłącza
```

Ustaw `METRICS_ENABLED=true` w pliku `.env`, flagą `-e METRICS_ENABLED=true` w
linii poleceń albo przez `export METRICS_ENABLED=true` (trzy sposoby uruchamiania
opisano w [Szybkim starcie](#domyślnie-wyłączone)), a następnie zrestartuj GoModel.

### Nie pojawiają się żadne dane metryk

**Przyczyna:** nie wykonano jeszcze żadnych requestów.

**Rozwiązanie:** wykonaj kilka requestów, aby wygenerować metryki:

<CodeGroup>

```bash curl
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-master-key" \
  -d '{"model": "gpt-4", "messages": [{"role": "user", "content": "Hi"}]}'

# Następnie sprawdź metryki
curl http://localhost:8080/metrics | grep gomodel_requests_total
```

```python Python
from openai import OpenAI

models = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="your-master-key",
)
models.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "Hi"}],
)

gateway = OpenAI(base_url="http://localhost:8080", api_key="your-master-key")
metrics = gateway.get("/metrics", cast_to=str)

for line in metrics.splitlines():
    if "gomodel_requests_total" in line:
        print(line)
```

```javascript JavaScript
import OpenAI from "openai";

const models = new OpenAI({
  baseURL: "http://localhost:8080/v1",
  apiKey: "your-master-key",
});
await models.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: "Hi" }],
});

const gateway = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: "your-master-key",
});
const metrics = await gateway.get("/metrics");

for (const line of metrics.split("\n")) {
  if (line.includes("gomodel_requests_total")) console.log(line);
}
```

</CodeGroup>

### Własny endpoint nie działa

**Przyczyna:** endpoint musi zaczynać się od `/`.

**Niepoprawnie:**

```bash
export METRICS_ENDPOINT=metrics  # Brak ukośnika na początku
```

**Poprawnie:**

```bash
export METRICS_ENDPOINT=/metrics  # Ukośnik na początku
```
