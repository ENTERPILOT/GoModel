## 概览

预算可让您为某个 `user_path` 子树、某个请求[标签](/zh/features/labelling)或某个提供商设置支出上限。GoModel 根据已追踪的用量成本记录评估预算，当某个上限已经用尽时，会拦截匹配的请求。

每个预算都有一个**作用域**，用于指明其限制的对象：

| 作用域       | 对象                         | 匹配                                        |
| ----------- | ------------------------------- | ---------------------------------------------- |
| `user_path` | 用户路径（`/team/alpha`）     | 该路径及其下的所有路径            |
| `label`     | 标签（`Mobile-App-iOS`）      | 携带该标签的所有请求              |
| `provider`  | 提供商名称（`openai-prod`） | 路由到该提供商实例的所有请求 |

当您需要以下这类上限时，可以使用预算：

- `/team/alpha` 每天可支出 `$10`
- `/team/alpha` 每周可支出 `$50`
- `/` 设置全局月度上限
- 所有带 `Mobile-App-iOS` 标签的请求每月可支出 `$500`
- `openai-prod` 提供商在所有用户范围内每天可支出 `$100`

<Info>
  只有在全局启用预算且当前工作流启用了 Budget 时，才会执行预算控制。全局预算功能开启时，工作流中的 Budget 控制默认启用。
</Info>

预算是软限制。请求在开始时依据已存储的支出决定是否放行，超出自身预算的故障转移目标会被跳过。用量按批写入，每 `USAGE_FLUSH_INTERVAL`（默认 5 秒）或每 100 条记录写入一次，因此预算还看不到正在收集的这一批中的请求，也看不到仍在运行的请求（例如长时间的流式请求）。这些请求会正常完成，其支出在写入后按预算的成本基准和[非计费提供商](#非计费提供商)规则计入预算。支出可能超出限额多少取决于流量和请求时长，并会在存储写入变慢时增大；因此当预算是客户的信用额度时，请留出余量。因缓冲区（`USAGE_BUFFER_SIZE`）已满或写入失败而从未被存储的用量记录会记入日志，并计入 `gomodel_usage_entries_dropped_total`，且永远不会计入预算。

## 启用预算

预算默认启用：

```env
BUDGETS_ENABLED=true
```

预算依赖用量追踪，因为支出是根据用量成本记录计算的：

```env
USAGE_ENABLED=true
```

如果禁用了用量追踪，GoModel 启动时会禁用预算管理，并记录一条警告日志。

## 创建预算

您可以在控制台中创建预算：

```text
Budgets -> Create Budget
```

<img

  alt="GoModel 控制台的 Budgets 页面，列出按用户路径设置的月度、每周和每日预算，并显示支出进度条和剩余金额"
  style={{ width: "100%", maxWidth: "1280px", height: "auto" }}
  className="rounded-lg"
/>

在表单中设置**作用域**、**对象**（用户路径、标签或提供商）、**周期**和**金额**；**Alert Thresholds** 为可选项，参见[告警](#告警)。之后，Budgets 页面上的每一行都会显示支出占上限的百分比、已支出金额与上限的对比，以及当前周期的剩余额度。标签和提供商预算会在周期旁显示 `label` 或 `provider` 标记。在控制台中创建的预算标记为 `manual`，从 YAML 或环境变量加载的预算标记为 `config`。

您也可以通过 YAML 预置预算：

```yaml
budgets:
  enabled: true
  user_paths:
    - path: "/team/alpha"
      limits:
        - period: "daily"
          amount: 10.00
        - period: "weekly"
          amount: 50.00
    - path: "/customers"
      # GoModel Pro：需要 quota_templates 授权。
      per_child: true
      limits:
        - period: "daily"
          amount: 5.00
    - path: "/"
      limits:
        - period: "monthly"
          amount: 500.00
  labels:
    - label: "Mobile-App-iOS"
      limits:
        - period: "monthly"
          amount: 500.00
  providers:
    - name: "openai-prod"
      limits:
        - period: "daily"
          amount: 100.00
```

或者使用环境变量：

```env
SET_BUDGET_TEAM__ALPHA="daily=10,weekly=50"
SET_BUDGET_="monthly=500"
# GoModel Pro（quota_templates 授权）：
SET_BUDGET_CUSTOMERS='[{"period":"daily","amount":5,"per_child":true}]'
SET_PROVIDER_BUDGET_OPENAI_PROD="daily=100"
```

`SET_BUDGET_` 之后的后缀会成为用户路径。路径段之间使用双下划线（`__`）分隔；单下划线仍属于路径段的一部分：

- `SET_BUDGET_TEAM__ALPHA` -> `/team/alpha`
- `SET_BUDGET_USER_123` -> `/user_123`
- `SET_BUDGET_` -> `/`

路径段中的字面量双下划线无法转义。对于需要包含 `__` 的路径段，请使用 YAML 或控制台。

提供商预算使用自己的前缀 `SET_PROVIDER_BUDGET_<NAME>`，与 `SET_PROVIDER_RATE_LIMIT_<NAME>` 类似。后缀中的下划线会转换为连字符，因此 `SET_PROVIDER_BUDGET_OPENAI_PROD` 限制的是 `openai-prod` 提供商。

<Note>
  标签预算没有环境变量形式。标签按原样匹配（包括大小写），并且可能包含环境变量名无法表示的字符。请在 YAML 的 `budgets.labels` 下声明，或通过控制台或 Admin API 创建。
</Note>

支持的标准周期如下：

| 周期    | 秒数   |
| --------- | --------- |
| `hourly`  | `3600`    |
| `daily`   | `86400`   |
| `weekly`  | `604800`  |
| `monthly` | `2592000` |

秒数列是内部的周期标识符。标准周期使用所配置的重置锚点逻辑；例如，`monthly` 以 `2592000` 存储，但会在日历月锚点重置，并在较短的月份中将重置日调整到该月最后一天。只有自定义的 `period_seconds` 值才会作为固定秒数的时间窗口。

如需自定义时间窗口，请在 YAML 中设置 `period_seconds`：

```yaml
budgets:
  user_paths:
    - path: "/team/alpha"
      limits:
        - period_seconds: 7200
          amount: 5.00
```

## 匹配规则

预算路径适用于所配置的路径及其后代路径：

- 预算路径 `/team`
- 请求路径 `/team/app`
- 结果：预算适用

同级路径不匹配：

- 预算路径 `/team`
- 请求路径 `/team-alpha`
- 结果：预算不适用

标签预算精确匹配标签，不进行子树匹配，也不忽略大小写：

- 预算标签 `Mobile-App-iOS`
- 请求标签 `["Mobile-App-iOS", "prod"]`
- 结果：预算适用

- 预算标签 `Mobile-App-iOS`
- 请求标签 `["mobile-app-ios"]`
- 结果：预算不适用

标签来自打标签规则、附加在认证该请求的托管 API 密钥上的标签，以及客户端发送的 LiteLLM tag；参阅[标签](/zh/features/labelling)。携带多个标签的请求会计入所有匹配的标签预算。LiteLLM tag 由客户端自行选择，因此当某个客户端不应计入其他团队的标签预算时，请设置 `LITELLM_TAGS_ENABLED=false`。

提供商预算匹配处理该请求的已配置提供商实例，不区分大小写。提供商预算限制的是该提供商在所有用户路径和标签范围内的总支出；它不会收窄用户路径或标签预算。准入时尚不知道提供商的请求（例如批处理提交和 MCP 调用）不会检查提供商预算。

如果有多个预算匹配同一请求，GoModel 会在一次查找中检查所有匹配的上限。只要任一匹配的上限已用尽，请求就会被拒绝。

### 非计费提供商

配置了 `billable: false` 的提供商所处理的请求，其成本不由调用方向您支付，典型情况是客户自己的 API 密钥被注册为一个独立的提供商实例。用户路径和标签预算既不会拦截路由到此类提供商的请求，也不会计入其支出，无论采用哪种成本基准。提供商预算仍然适用于它：基于提供商成本时会完整计入其用量，而基于计费成本的提供商预算看到的是其为 `0` 的计费成本。用量仍会照常追踪和定价，并且每条记录都会记下 `billable: false`；该标记在写入记录时确定，因此之后更改它不会改写过去的支出。

例如，某个平台允许用户自带 OpenAI 密钥，同时也提供您托管的模型。将该用户的密钥注册为一个独立的提供商，将其标记为非计费，并把预算设置在该用户的路径上：这样预算只限制托管模型，而该用户的 OpenAI 用量仍然会出现在用量报告和 `GET /v1/usage` 中。

```bash
curl -X PUT http://localhost:8080/admin/provider-credentials \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "openai-u123", "type": "openai", "api_keys": ["sk-..."], "billable": false}'
```

```yaml
budgets:
  user_paths:
    - path: "/users/u123"
      limits:
        - period: "monthly"
          amount: 20.00
```

将该用户的 API 密钥绑定到 `/users/u123`。发往 `openai-u123/...` 的请求不会检查该预算，也不会计入其中；发往您托管的提供商的请求则会。在 `config.yaml` 中，同一设置为 `providers.<name>.billable: false`，环境变量形式为 `<PROVIDER>[_SUFFIX]_BILLABLE=false`；非计费用量如何计费，参见[成本追踪](/zh/features/cost-tracking#加价与计费成本)。

### 提供商预算与故障转移

当某个提供商预算已用尽且请求配置了[故障转移](/zh/features/failover)目标时，GoModel 会跳过该已用尽的提供商并尝试故障转移目标，而不是拒绝请求。故障转移也会跳过自身提供商预算已用尽的任何目标。如果没有剩余目标，客户端会收到原始的 `budget_exceeded` 错误。用户路径和标签预算始终直接拒绝：切换提供商无法缓解这类预算。

唯一的例外是在非计费提供商上被准入的请求，此时未检查用户路径和标签预算。当它故障转移到计费目标时，故障转移会针对该目标检查这些预算，并在任一预算已用尽时跳过该目标，因此客户自己的密钥绝不会成为绕过其在您的提供商上预算的途径。

### 动态的子路径预算

<Info>
  动态的子路径预算在 GoModel Pro 中提供，需要 `quota_templates` 许可证授权。没有该授权时，Admin API 写入会被拒绝并返回 403 `quota_templates_not_entitled`，配置中的 `per_child: true` 会导致启动中止。GoModel 绝不会静默回退为一个共享的子树预算，因为那会改变执行语义。
</Info>

当某个用户路径条目的上限应作为其直接子路径的模板，而不是一个共享的子树预算时，请在该条目上设置 `per_child: true`。以 `/customers` 上的模板为例：

- `/customers/alice` 和 `/customers/alice/app` 从 Alice 的预算中支出
- `/customers/bob` 从独立的 Bob 预算中支出
- `/customers` 本身不匹配该模板，因为它没有子路径

控制台会将该定义显示为 `per child` 模板，而不会虚构一个汇总用量值。使用 `GET /v1/usage` 并传入某个子路径的有效用户路径，即可查看该子路径解析后的预算。重置该模板会为其所有子路径开始一个新周期。

## 基于计费成本的预算（GoModel Pro）

<Info>
  基于计费成本的预算需要带有 `billing` 授权的 GoModel Pro 许可证，并设置
  `PRICING_MARKUPS_ENABLED=true`。缺少任一条件时，管理 API 会拒绝带有
  `"cost_basis": "billed"` 的写入（403 `billed_budgets_not_entitled`；加价关闭时为
  400 `billed_budgets_markups_disabled`），当前配置中的计费预算会中止启动。已存储的计费预算（在仪表盘中创建，或来自之前的配置）不会阻止启动：在授权或加价缺失期间，GoModel
  只记录一次警告，并按提供商成本执行该预算，因此限额仍然有效。它仍以计费预算的形式保存：在仪表盘中或使用 `"cost_basis": "billed"` 修改金额后仍是计费预算；授权和加价恢复后，它会重新限制计费成本。
</Info>

默认情况下，预算限制的是提供商成本：即您为未缓存请求向上游支付的费用。设置
`cost_basis: billed` 后，预算改为限制向调用方计费的金额——提供商成本加上
[加价](/zh/features/cost-tracking)。当预算是客户的信用额度时使用它。

```yaml
budgets:
  labels:
    - label: "customer-acme"
      limits:
        - period: "monthly"
          amount: 500.00
          cost_basis: "billed"
```

```bash
curl -X PUT http://localhost:8080/admin/budgets \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "label",
    "subject": "customer-acme",
    "cost_basis": "billed",
    "budget_key": { "period": "monthly" },
    "amount": 500.00
  }'
```

计费预算：

- 累计 `billed_cost`，包括计费的响应缓存命中。设置
  `PRICING_BILL_CACHE_HITS=false` 时，缓存命中按 `0` 计费，不计入预算。
- 对没有计费成本的用量（在启用加价之前记录）按其提供商成本计入，因此在周期中途启用加价也不会少算。
- 同样约束响应缓存命中：在缓存命中计费期间，已用尽的计费用户路径或标签预算会在回放缓存响应之前拒绝请求。基于提供商成本的预算从不计入缓存命中，提供商预算也不适用于缓存命中，因为命中不会路由到任何提供商。[非计费提供商](#非计费提供商)模型的命中无论如何都会被准入，正如该请求本身也会被准入一样。
- 用于提供商时，仍会将该提供商模型的计费缓存命中计入支出。设置
  `BUDGETS_PROVIDER_BILLED_CACHE_HITS=false`（`budgets.provider_billed_cache_hits`）后，只限制该提供商实际处理的请求的计费金额。

`cost_basis` 为 `provider`（默认）或 `billed`。它是一个属性，而不是预算键的一部分：同一作用域、主体和周期只对应一个预算，可使用任一基准；更改基准不会重置当前周期。不带
`cost_basis` 的 `PUT` 会设置为 `provider`；现有预算继续限制提供商成本。`GET /admin/budgets`
和 `GET /v1/usage` 会报告每个预算保存的 `cost_basis` 和 `enforced_cost_basis`（`spent` 的计算基准）。只有按提供商成本执行的计费预算两者才不同。在仪表盘中，授权和加价都开启后，预算表单会显示**成本基准**选择器，计费预算会带有 `计费` 标签，按提供商成本执行的计费预算会带有 `计费 · 按提供商成本` 标签。

## 工作流控制

当前工作流决定是否对某个请求执行预算检查。

在工作流负载中：

```json
{
  "schema_version": 1,
  "features": {
    "budget": true,
    "cache": true,
    "audit": true,
    "usage": true,
    "guardrails": true,
    "failover": true
  }
}
```

使用带作用域的工作流，可以针对某个提供商、模型或 `user_path` 子树开启或关闭预算控制。匹配优先级请参阅[工作流](/zh/advanced/workflows)。

<Note>
  响应缓存命中可能在预算控制之前返回。如果存在缓存的响应，GoModel 可以直接返回它，而不会产生额外的提供商费用。
</Note>

## 重置窗口

预算重置锚点在控制台的以下位置配置：

```text
Settings -> Budget Resets
```

重置设置按 UTC 时间计算。

对于月度预算，如果所配置的日期在某个月中不存在，则在该月最后一天重置。例如，月度重置日设为 `31` 时，会在 4 月 30 日以及 2 月 28 日或 29 日重置。

编辑预算会更改上限，但不会重置当前周期。使用行级的 Reset 操作可为单个预算开始新周期，使用 `Settings -> Reset All Budgets` 可重置所有预算。

## 告警

预算用尽后会拒绝请求。告警会在此之前通知你：每个预算都有阈值（金额的百分比），支出达到某个阈值时，GoModel 发送一条告警。

在有投递目标之前，告警处于关闭状态。声明一个 webhook 后，每个预算都会在默认阈值 80% 和 100% 时告警：

```env
BUDGETS_ALERTS_WEBHOOK_URL=https://alerts.example.com/gomodel
BUDGETS_ALERTS_WEBHOOK_SECRET=${file:/run/secrets/alert_webhook_secret}
```

```yaml
budgets:
  alerts:
    thresholds: [80, 100]
    webhooks:
      - url: "https://alerts.example.com/gomodel"
        secret: "${env:BUDGET_ALERT_WEBHOOK_SECRET}"
```

URL 和 secret 都支持[密钥引用](/zh/advanced/secret-references)。环境变量声明一个 webhook，并替换 YAML 中的列表；需要多个 webhook 时请使用 YAML。

| 设置（`budgets.alerts.`） | 环境变量                             | 默认值    | 何时修改                                         |
| ------------------------- | ------------------------------------ | --------- | ------------------------------------------------ |
| `thresholds`              | `BUDGETS_ALERTS_THRESHOLDS`          | `80,100`  | 希望更早收到提醒（`50,80,100`）。每个值为 1-100。 |
| `interval`                | `BUDGETS_ALERTS_INTERVAL`            | `60`      | 需要在支出入库后一分钟内更快告警。单位为秒。     |
| `webhooks`                | `BUDGETS_ALERTS_WEBHOOK_URL`、`_SECRET` | _（无）_ | 必须设置：没有 webhook 就不会评估任何内容。      |
| `webhook_timeout`         | `BUDGETS_ALERTS_WEBHOOK_TIMEOUT`     | `10`      | 接收端较慢。每次尝试的秒数。                     |
| `webhook_max_retries`     | `BUDGETS_ALERTS_WEBHOOK_MAX_RETRIES` | `3`       | 设为 `0` 则从不重试；最大为 `10`。               |

### 单个预算的阈值

预算可以有自己的阈值，用来替换默认值。可在预算表单中设置 **Alert Thresholds**，在 Admin API 中设置 `alert_thresholds`，或写入配置：

```yaml
budgets:
  user_paths:
    - path: "/team/alpha"
      limits:
        - period: "monthly"
          amount: 500.00
          alert_thresholds: [50, 75, 90]
```

```env
SET_BUDGET_TEAM__ALPHA='[{"period":"monthly","amount":500,"alert_thresholds":[50,75,90]}]'
```

空列表表示使用默认值。Budgets 页面会显示每个预算的阈值；尚未配置投递目标时标记为 `inactive`。

### 何时触发告警

GoModel 在后台每隔 `interval` 秒评估一次预算，从不在处理请求时评估。每个预算、周期和阈值只触发一次告警：

- 共享同一数据库的多个副本合计只发送一次：实例先把告警记录写入数据库再投递，只有第一条记录生效。使用 SQLite 时每个实例有自己的数据库，各自告警。
- 新周期或[重置](#重置窗口)会重新开始，可以再次触发。在周期中途提高预算金额，不会让本周期内已达到的阈值重新生效。
- 如果两次评估之间支出越过了多个阈值，每个阈值都会触发，从最低的开始。
- [子路径预算](#动态的子路径预算)按子路径告警：每个子路径达到的是自己预算的阈值。
- 支出读取自已入库的用量，因此告警相对于触发它的请求会有延迟：用量刷新间隔（`USAGE_FLUSH_INTERVAL`，5 秒）加上最多一个评估间隔。

记录在投递之前写入，因此告警最多投递一次：网关在两者之间被停止时，这条告警会丢失；重试后仍无法投递的告警会被记录到日志并计数，不会稍后补发。

### Webhook 负载

每条告警是一次带 JSON 请求体的 `POST`：

```json
{
  "type": "budget.threshold_reached",
  "id": "bgt_5f0c2a9d41b7e3a86c1d02ef",
  "timestamp": "2026-04-25T12:00:07Z",
  "budget": {
    "scope": "user_path",
    "subject": "/customers",
    "effective_subject": "/customers/alice",
    "per_child": true,
    "period_seconds": 86400,
    "period": "daily",
    "amount": 100,
    "cost_basis": "provider"
  },
  "threshold_percent": 80,
  "spent": 81.2,
  "usage_ratio": 0.812,
  "period_start": "2026-04-25T00:00:00Z",
  "period_end": "2026-04-26T00:00:00Z",
  "projected_spend": 162.4
}
```

| 字段                       | 含义                                                                         |
| -------------------------- | ---------------------------------------------------------------------------- |
| `type`                     | `budget.threshold_reached`。请忽略未知类型：以后可能增加。                   |
| `id`                       | 标识这条告警。同一告警的重试带有相同的 `id`，请据此去重。                    |
| `timestamp`                | GoModel 发出告警的时间（UTC）。                                              |
| `budget.scope`、`.subject` | 预算：`user_path`、`label` 或 `provider`，以及它的对象。                     |
| `budget.effective_subject` | 支出实际归属的对象：子路径预算为子路径，否则为对象本身。                     |
| `budget.period_seconds`、`.period` | 重置周期及其名称（`hourly`、`daily`、`weekly`、`monthly` 或 `<n>s`）。 |
| `budget.amount`、`.cost_basis` | 限额，以及 `spent` 所依据的成本（`provider` 或 `billed`）。              |
| `threshold_percent`        | 达到的阈值。                                                                 |
| `spent`、`usage_ratio`     | 发出告警时本周期的支出，以及 `spent / amount`（超出时大于 `1`）。            |
| `period_start`、`period_end` | 告警所属的周期。重置会把 `period_start` 移到重置时间。                     |
| `projected_spend`          | 参见[支出预测](#支出预测)。周期经过的时间太短时省略。                        |

字段只会增加。每次投递还带有以下请求头：

| 请求头                | 值                                                                       |
| --------------------- | ------------------------------------------------------------------------ |
| `X-GoModel-Event`     | 告警的 `type`                                                            |
| `X-GoModel-Delivery`  | 告警的 `id`                                                              |
| `X-GoModel-Signature` | `sha256=<hex>`：以 webhook 的 `secret` 为密钥，对原始请求体计算的 HMAC-SHA256。仅在设置了 secret 时发送。 |

请在解析之前，针对原始请求体校验签名：

```python
import hashlib, hmac

def verified(secret: bytes, body: bytes, header: str) -> bool:
    expected = "sha256=" + hmac.new(secret, body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)
```

以任意 `2xx` 响应即可。网络错误、`408`、`429` 或 `5xx` 最多重试 `webhook_max_retries` 次，两次尝试之间等待 1 秒、2 秒、4 秒，依此类推（最长 30 秒）；其他状态码不重试。不会跟随指向其他主机的重定向。投递使用网关的出站代理（`HTTPS_PROXY`）和 TLS 信任配置（`http.tls`）。某个 webhook 不可用，不会拖慢其他预算的评估，也不会影响其他 webhook。

webhook 有意保持为通用 JSON：GoModel 不会为 Slack、Teams 或电子邮件格式化消息。请把它指向一个负责格式化的小型接收服务或自动化工具；在自定义构建中，也可以注册一个 `ext.AlertSink`，它会收到相同的事件。

有两个 Prometheus 计数器跟踪告警：`gomodel_budget_alerts_fired_total`（`scope`、`threshold`）和 `gomodel_budget_alert_delivery_failures_total`（`destination`）；参见 [Prometheus 指标](/zh/guides/prometheus-metrics#针对未投递的预算告警进行告警)。

## 支出预测

`GET /admin/budgets` 和 Budgets 页面会显示每个预算的走向：

- `projected_spend`：如果按目前的速度继续支出，周期结束时的支出，即 `spent / period_ratio`。
- `projected_exhaustion_at`：按该速度预算何时用尽。仅当预测值超过金额且预算尚未用尽时出现。

预测是线性的，会把周期早期的突发当作整个周期的速度。因此在周期经过 5% 之前（一天中的 72 分钟，一个月中约一天半），这两个字段都会省略；如果发生过重置，则从重置时起算。子路径模板没有预测，因为它没有单一的支出值。

## Admin API

预算管理也可以通过 Admin API 进行：

<CodeGroup>

```bash curl
curl -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  http://localhost:8080/admin/budgets
```

```python Python
import os

import httpx
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080",
    api_key=os.environ["GOMODEL_MASTER_KEY"],
)
budgets = client.get("/admin/budgets", cast_to=httpx.Response)

print(budgets.json())
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: process.env.GOMODEL_MASTER_KEY,
});

const budgets = await client.get("/admin/budgets");
console.log(budgets);
```

</CodeGroup>

响应中的每个预算都带有其状态（`spent`、`remaining`、`usage_ratio`、`period_ratio`）、[预测](#支出预测)（`projected_spend`、`projected_exhaustion_at`），以及自己的 `alert_thresholds`（如果设置了）。顶层的 `alerts` 对象说明告警是否启用（`enabled`，即存在投递目标）以及 `default_thresholds`。

创建或更新预算。预算由其 `scope`、`subject` 和周期唯一标识；对于用户路径预算，可以使用 `user_path` 作为 subject 的简写形式。`alert_thresholds` 是可选的：不带该字段的 `PUT` 会让预算恢复使用默认阈值。

<CodeGroup>

```bash curl
curl -X PUT http://localhost:8080/admin/budgets \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "user_path",
    "subject": "/team/alpha",
    "per_child": false,
    "budget_key": { "period": "daily" },
    "amount": 10.00,
    "alert_thresholds": [50, 90]
  }'
```

```python Python
import os

import httpx
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080",
    api_key=os.environ["GOMODEL_MASTER_KEY"],
)
budget = client.put(
    "/admin/budgets",
    cast_to=httpx.Response,
    body={
        "scope": "user_path",
        "subject": "/team/alpha",
        "budget_key": {"period": "daily"},
        "amount": 10.00,
    },
)

print(budget.json())
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: process.env.GOMODEL_MASTER_KEY,
});

const budget = await client.put("/admin/budgets", {
  body: {
    scope: "user_path",
    subject: "/team/alpha",
    budget_key: { period: "daily" },
    amount: 10.0,
  },
});

console.log(budget);
```

</CodeGroup>
