Kimi Code 是一个兼容 OpenAI 的编程助手，服务地址为 `https://api.kimi.com/coding/v1`。GoModel 通过共享的 OpenAI 适配器路由聊天、模型列表、嵌入（Embeddings）和透传请求。`/v1/responses` 端点会以原生方式转发到上游的 Responses API，而不是通过 Chat Completions 进行转换；上游端点不支持文件和批处理。

Kimi Code 不保留任何响应。带有 `store: true` 的请求会被改写为 `store: false`（上游会以 400 拒绝 `store: true`）。链式调用只能通过 GoModel 实现：配置了响应存储后，网关会在分发请求之前将已存储的历史记录回放到请求中，从而展开 `previous_response_id` 链；`conversation` 引用也会以同样的方式通过会话存储进行解析。如果没有这些存储，携带 `previous_response_id` 或 `conversation` 的请求会以 invalid-request 错误被拒绝，因为上游永远无法解析所引用的状态。

## 配置

```bash
KIMICODE_API_KEY=...
```

或在 `config.yaml` 中配置：

```yaml
providers:
  kimicode:
    type: kimicode
    base_url: "https://api.kimi.com/coding/v1"
    api_key: "${KIMICODE_API_KEY}"
```

<Note>
  提供商的 `type` 为 `kimicode`（不带连字符）。配置键（上例中的 `kimicode`）可以任意命名，仅用于在您的配置中标识该条目，可以修改。
</Note>

您还可以通过以下变量覆盖 Base URL 和模型列表：

```bash
KIMICODE_BASE_URL=https://api.kimi.com/coding/v1
KIMICODE_MODELS=kimi-for-coding,bge_m3_embed
```

## 模型

标准的聊天模型别名为 `kimi-for-coding`。您可以在虚拟模型中引用它，也可以通过兼容 OpenAI 的 `/v1/chat/completions` 端点直接调用。

```yaml
virtual_models:
  - source: kimi-coding
    target: kimicode/kimi-for-coding
```

## 嵌入

Kimi Code 提供用于嵌入的 `bge_m3_embed`，但上游并未为该模型提供文档。请将其视为实验性功能：在生产工作流中依赖它之前，请先在您的账户中测试其可用性和维度。

## 定价与配额

Kimi Code 没有公布按 Token 计费的价格。由于 GoModel 的用量成本追踪没有可用的单价，Kimi Code 请求的 `cost` 会报告为零。`cost` 负载均衡策略无法按价格优先选择或排序该提供商，但当没有已定价的提供商可用时，仍可能回退到 Kimi Code。

上游配额按每周刷新，外加一个滚动的五小时窗口。请为突发限制做好规划，并优先使用保守的按提供商重试覆盖设置：

```yaml
providers:
  kimicode:
    type: kimicode
    base_url: "https://api.kimi.com/coding/v1"
    api_key: "${KIMICODE_API_KEY}"
    retries: 3
```
