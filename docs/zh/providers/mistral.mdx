Mistral AI（La Plateforme）通过 `https://api.mistral.ai/v1` 提供 OpenAI 兼容 API。GoModel
通过共享的 OpenAI 适配器路由聊天补全、模型列表、Embedding 与透传请求；`/v1/responses`
端点通过聊天补全进行翻译。该提供商不提供文件和批处理。

## 推理（思考）输出

在推理模型上（例如 `mistral-large-latest`、`mistral-small-latest`，以及托管的推理模型如
Z.ai GLM），Mistral 将助手内容作为**类型化分块列表**返回——推理轨迹是 `thinking` 分块，
回答是 `text` 分块——同时在缓冲响应和 SSE 流中。这种格式不是标准的 OpenAI 聊天输出，
SillyTavern 等客户端会将其渲染为乱码。

GoModel 的 `mistral` 提供商会自动将其转换为标准格式：

- `thinking` 分块合并为 `reasoning_content` 字段；
- `text` 分块合并为纯字符串 `content`。

流式（`choices[].delta`）与非流式（`choices[].message`）响应均适用此转换。无需任何客户端配置。
没有标准聊天对应形式的分块类型（此端点上尚无已知类型）会保留在 `mistral_content_chunks`
厂商成员中，因此不会丢失任何上游数据。

请使用标准的嵌套参数发送推理力度；GoModel 会将其映射为 Mistral 的扁平 `reasoning_effort`：

```json
{
  "model": "mistral-large-latest",
  "messages": [{ "role": "user", "content": "17 * 23 是多少？" }],
  "reasoning": { "effort": "high" }
}
```

Mistral 的 API 级枚举为 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，
该值将原样透传。每个模型接受哪些档位因模型而异——例如 Mistral Large 4 接受
`low`/`medium`/`high`，托管的 GLM 模型接受 `low`/`high`/`max`——因此为所选模型传入不
支持的档位会被 Mistral 自身拒绝，这与使用 Mistral 自家 SDK 的行为一致。

当客户端回放先前的助手回合时，GoModel 会在转发前删除其 `reasoning_content` 与
`mistral_content_chunks` 成员，因为 Mistral 会以 422 拒绝这些未知成员。

## 配置

```bash
MISTRAL_API_KEY=...
```

或在 `config.yaml` 中：

```yaml
providers:
  mistral:
    type: mistral
    base_url: "https://api.mistral.ai/v1"
    api_key: "${MISTRAL_API_KEY}"
```

<Note>
  提供商 `type` 为 `mistral`。配置键（上例中的 `mistral`）是任意的，仅用于在配置中标识
  此条目，可以更改。
</Note>

您还可以覆盖基础 URL 和模型列表：

```bash
MISTRAL_BASE_URL=https://api.mistral.ai/v1
MISTRAL_MODELS=mistral-large-latest,mistral-small-latest,mistral-embed
```

<Note>
  在默认的 `allowlist` 模式下，设置 `MISTRAL_MODELS` 会将此提供商服务的模型限制为该
  列表——其他模型的请求返回 404。
  [Models modes](/advanced/config-yaml#models-modes) 提供了 `merge`/`fallback` 替代方案。
  404 仅适用于基于模型的路由：当运营者为该提供商启用透传（`ENABLED_PASSTHROUGH_PROVIDERS`，
  参见 [Passthrough](/features/passthrough-api)）时，`/p/mistral/...` 请求不受此列表限制，
  仍会到达上游。
</Note>

## 模型

使用 `GET /v1/models` 列出您的 API 密钥可用的模型，或通过 OpenAI 兼容的
`/v1/chat/completions` 端点直接调用：

```yaml
virtual_models:
  - source: mistral
    target: mistral/mistral-large-latest
```

## Embedding

Mistral 的 `/v1/embeddings` 端点（例如 `mistral-embed`）受支持。
