## 概览

OIDC SSO 用于保护控制台，支持带 PKCE 的授权码（Authorization Code）流程、state 和 nonce 校验、服务发现，以及经过签名的 `HttpOnly`、
`SameSite=Lax` 会话。

与其他 Pro 功能不同，显式启用的 SSO 配置采用失败即拒绝（fail closed）策略：当缺少 `sso` 授权或配置无效时，启动会中止，以确保认证边界不会悄无声息地消失。

## 配置 SSO

在 GoModel 主 YAML 配置的 `extensions.sso` 下进行配置：

```yaml
extensions:
  sso:
    enabled: true
    issuer_url: https://login.example.com
    client_id: gomodel
    client_secret: ${PRO_SSO_CLIENT_SECRET}
    redirect_url: https://gomodel.example.com/sso/callback
    session_secret: ${PRO_SSO_SESSION_SECRET}
    admin_groups: [gomodel-admins]
```

`PRO_SSO_*` 环境变量会覆盖 YAML 中的值。重定向 URL
必须以 `/sso/callback` 结尾（包括已配置的 `BASE_PATH`），并且除本地回环开发 URL 外均要求使用 HTTPS。默认情况下，至少需要一个管理员组；只有对于有意不加限制的 OIDC 客户端，才应设置 `PRO_SSO_ALLOW_ALL_ADMINS=true`。

## 跨副本退出登录

退出登录会立即在处理该请求的副本上吊销会话，并将吊销记录写入已配置的存储后端。每个副本每 2 秒重新读取一次吊销记录，因此使用 PostgreSQL 或 MongoDB 存储时，已退出的会话会在几秒内在所有副本上失效。吊销记录在重启后依然保留，并在会话本应过期后删除。

使用 SQLite 时请只运行一个副本：每个 SQLite 实例都有自己的数据库，其他副本永远看不到吊销记录，重放的 Cookie 在这些副本上会一直有效，直到过期。如果退出登录时存储后端不可达，吊销仍会在处理该请求的副本上生效，并记录一条警告，该副本会持续重试，直到其他副本能够看到它。

## 审计与访问控制

成功登录、被策略拒绝的登录以及退出登录都会被记录为经过脱敏的审计事件。Token、授权码、Cookie、原始声明（claims）以及身份提供商的错误详情均不会被存储。

SSO 会话与托管 API 密钥一样携带 `user_path`，因此 [用户](/zh/features/users) 页面上组级和用户级的模型允许列表，同样适用于通过 SSO 会话发出的请求。按密钥设置的 `allowed_models` 是托管
API 密钥的设置，不适用于 SSO 会话。
