GoModel estimates the cost of every tracked request from model pricing and shows the totals on the dashboard.

<Warning>
  These costs are **estimates**, not a billing record. Unless a provider reports
  an exact cost, GoModel multiplies the tokens a provider reports by that model's
  configured rates, so discounts, promotions, and provider-side rounding are not
  reflected. Treat the provider's dashboard as the source of truth, and check
  GoModel figures against it before using them for invoicing or reconciliation.
</Warning>

## How costs are estimated

For each request GoModel prices:

- **Input** and **output** tokens at the model's per-million-token (MTok) rates.
- **Cached input**, **reasoning**, and **audio** tokens at their own rates when the provider reports them, so cache-heavy and reasoning-heavy traffic is priced correctly.
- **Non-token units** where that is how the provider bills: generated images (`per_image` / `output_image_per_mtok`), audio duration (`per_second_input`, `per_second_output`), and speech characters (`per_character_input`). See [images](/advanced/images-api#cost-tracking) and [audio](/advanced/audio-api#cost-tracking) for which unit applies to which model — where a rate and a token rate are two expressions of the same charge (an image's generated tokens, an audio clip's duration), only one of them is applied.

When a provider returns an exact cost (OpenRouter credits, xAI `cost_in_usd_ticks`), GoModel uses that value instead of catalog pricing. Each row records which method was used in its `cost_source` field: `model_pricing`, `openrouter_credits`, or `xai_cost_in_usd_ticks`.

<Note>
  Cached tokens are discounted only when the model's pricing includes a
  `cached_input_per_mtok` rate. Without it, they are priced at the full input rate.
</Note>

Anthropic bills cache writes by TTL: the default 5-minute writes at `cache_write_per_mtok` and 1-hour writes (`"ttl": "1h"`) at `cache_write_1h_per_mtok`. GoModel prices each share at its own rate from the `usage.cache_creation` split. Without a `cache_write_1h_per_mtok` rate, 1-hour writes are priced at `cache_write_per_mtok`.

## Time-of-day pricing

Some providers charge different rates depending on when a request runs. DeepSeek, for example, bills its off-peak hours at half the peak rates and treats weekends as off-peak. The catalog publishes the standard (peak) rates as a model's base prices and lists the discounted periods under `pricing.time_windows`:

```json
"pricing": {
  "input_per_mtok": 0.44,
  "output_per_mtok": 1.32,
  "cached_input_per_mtok": 0.014,
  "time_windows": [
    {
      "label": "off_peak",
      "utc_ranges": [
        { "days": ["mon", "tue", "wed", "thu", "fri"], "start": "00:00", "end": "01:00" },
        { "days": ["mon", "tue", "wed", "thu", "fri"], "start": "04:00", "end": "06:00" },
        { "days": ["mon", "tue", "wed", "thu", "fri"], "start": "10:00", "end": "24:00" },
        { "days": ["sat", "sun"], "start": "00:00", "end": "24:00" }
      ],
      "pricing": { "input_per_mtok": 0.22, "output_per_mtok": 0.66, "cached_input_per_mtok": 0.007 }
    }
  ]
}
```

GoModel prices each request with the rates in effect at the moment it completed, evaluated in **UTC** regardless of the server's or the dashboard's timezone. Ranges are half-open (`start` inclusive, `end` exclusive); an `end` at or before `start` wraps past midnight, and `days` limits a range to weekdays (all days when omitted). Rates absent from a window keep their base price, and outside every window the base prices apply. Recalculating stored costs uses each row's stored timestamp, so historical rows are re-priced for the window they actually fell in. The dashboard's cached-input cost estimate applies windows per minute of the week, matching the precision of the window bounds.

On the **Models** page, a `*` next to a price marks a model with time windows; hover it to see the schedule and rates. Overriding a base rate (input, output, cached input, or cache write) replaces the catalog's discount for that rate as well: the override becomes the price at every hour. `config.yaml` model metadata may also declare its own `time_windows`, which replace the catalog's.

<Note>
  Time windows are recurring UTC schedules only. Rules the catalog cannot
  express — a provider's holidays, or promotions with a fixed end date — are
  not applied.
</Note>

## Where pricing comes from

Pricing for a model is resolved in priority order:

1. Operator **overrides** set in the dashboard.
2. **`config.yaml`** `providers.<name>.models` metadata.
3. The **model catalog**, sourced from the [`ai-model-list`](https://github.com/ENTERPILOT/ai-model-list) registry.

The catalog supplies the default pricing for most models. If a model's price looks wrong or a rate is missing (for example, a cached-input rate), check it against [`ai-model-list`](https://github.com/ENTERPILOT/ai-model-list) and contribute a correction there, or set an override for an immediate fix.

Pricing is one part of a wider metadata pipeline that also resolves context windows, capabilities, and model categories — see [Model metadata](/advanced/model-metadata) for the full source chain.

## Override pricing

Override pricing when the catalog price is wrong, missing, or differs from your negotiated rate. Open the **Models** page, find the model, and open its **Pricing override** editor. Set one or more price types (input, output, cached input, and so on) in USD. Saved fields override catalog and `config.yaml` pricing for that selector; unset fields keep inheriting.

## Markups and billed cost

Add a markup when you resell model access, for example to recharge customers for the tokens they use. GoModel records each request's **billed cost** (`billed_cost` on the usage row): the provider cost plus the markup. The provider cost itself never changes, so budgets, dashboard totals, and savings keep measuring what you pay upstream. With GoModel Pro, a budget can limit billed cost instead; see [Budgets on billed cost](/features/budgets#budgets-on-billed-cost-gomodel-pro).

Markups are off by default. Turn them on with `markups_enabled: true` (env `PRICING_MARKUPS_ENABLED=true`), then set percentages in `config.yaml`. With markups on but no rule matching a request, its billed cost equals its provider cost. With markups off, GoModel records no billed cost and ignores `markups` and `bill_cache_hits`, logging a warning at startup if `markups` is set.

```yaml
pricing:
  markups_enabled: true # env: PRICING_MARKUPS_ENABLED; default false
  bill_cache_hits: true # env: PRICING_BILL_CACHE_HITS; default true
  markups:
    "/": 15                         # every model
    "openai/": 10                   # one provider instance
    "gpt-5": 20                     # a model on any provider
    "anthropic/claude-opus-4-1": 25 # one model on one provider
```

The most specific selector wins, in this order: provider/model, model, provider, global. Markups never stack. A provider selector names the configured instance (the key under `providers`), and an unknown provider fails startup. A 20% markup bills $1.20 for $1.00 of provider cost: a 16.7% margin.

`bill_cache_hits` decides how responses served from GoModel's response cache are billed. `true` bills each hit at what the same call would cost when the hit is served — current pricing and time-of-day rates — plus markup; `false` bills them at $0, even when their cost is unknown. Provider prompt caching (cached input tokens) is a real provider cost and is always billed.

Each usage row also stores the markup it was billed at (`markup_percent`, `markup_selector`), so changing markups never rewrites past bills.

Once markups are enabled, the dashboard shows billed cost next to provider cost: a **Billed** card on the overview and usage pages, a column in every usage breakdown (model, user path, label, request type or endpoint, and session), and a column in the request log whose tooltip names the markup each row was billed at. The admin API reports it as `total_billed_cost` on `/admin/usage/summary`, `billed_cost` on `/admin/usage/daily`, `/admin/usage/models`, `/admin/usage/user-paths`, `/admin/usage/labels`, `/admin/usage/endpoints`, and `/admin/usage/sessions`, and `billed_cost`, `markup_percent`, and `markup_selector` on `/admin/usage/log` entries. A day billed only for cache hits still appears in `/admin/usage/daily`, with zero requests. Billed totals include billed cache hits even though the other cost figures exclude them, so per-user-path billed cost is what to charge each customer.

### Per-customer markups (GoModel Pro)

<Info>
  Per-customer markups are available in GoModel Pro and require the
  `billing` license entitlement. Without it, `user_path_markups` with
  markups enabled aborts startup — GoModel never silently bills a customer at
  the global rate.
</Info>

Give each customer, identified by its [user path](/features/user-path) subtree, its own markups with `user_path_markups`. Each path takes the same selectors as `markups`:

```yaml
pricing:
  markups_enabled: true
  markups:
    "/": 20             # everyone else
  user_path_markups:
    /acme:
      "/": 30           # /acme and everything below it
      "openai/gpt-5": 15
    /acme/internal:
      "/": 0            # internal traffic at cost
```

GoModel takes the deepest configured path that covers the request's user path (`/acme` covers `/acme/team`, not `/acmecorp`) and applies the most specific selector in it, in the usual order. When that path has no matching selector, it tries the next shallower path, then `markups`. Markups never stack. With the example above, `/acme/internal/ci` is billed at 0%, `/acme/team` at 15% for `openai/gpt-5` and 30% for everything else, and `/beta` at 20%.

The default is none: without `user_path_markups`, `markups` applies to everyone. With `markups_enabled: false`, `user_path_markups` is ignored like `markups`, and GoModel logs a warning at startup. A rule from `user_path_markups` is recorded in `markup_selector` as `<user path>:<selector>`, for example `/acme:openai/gpt-5`, so the request log shows which customer rule was billed. User paths are normalized as on requests, so `acme/` and `/acme` are the same key; `/` is rejected, since `markups` already covers it.

## Dashboard totals

- **Estimated Cost** — spend on live provider requests; cache hits are excluded.
- **Saved Cost** — what requests served from the cache would otherwise have cost.
- **Billed** — shown when markups are enabled: provider cost plus markup, including billed cache hits.

A `---` value means the cost is unknown because no pricing was available, which is not the same as `$0`.

## Filter and break down spend

The usage page filters every card, chart, and the request log by model, provider, label, API key, endpoint, user path, and session. Each dropdown takes several values: a request matches a filter when it has any of the selected values, and it must match every filter. The user path picker lists known paths as a tree grouped by prefix; picking a node includes everything below it, and you can type a path that is not listed.

The **Breakdown** section pivots the filtered usage by two dimensions. For example, rows **User path**, columns **Period** and period **Monthly** show cost per month per user path. Pick the metric (cost, tokens, or requests); the top 10 rows and columns are kept and the rest fold into **Other**. **User path grouping** folds paths by their first segments, so `/team/alice/laptop` counts under `/team/alice`. Switch between the stacked chart and the table, and use **Download CSV** to export the table with its totals.

Filters, the date range, and the breakdown settings are kept in the page URL, so a copied link opens the same view. The same data is available from [`GET /admin/usage/breakdown`](/advanced/admin-endpoints#get-adminusagebreakdown), and the filters from every usage endpoint except `/admin/usage/throughput` (see [Multi-value filters](/advanced/admin-endpoints#multi-value-filters)).

## Recalculate stored costs

Recalculating recomputes the stored cost of matching usage rows from current pricing. Use it after changing an override, or when pricing was unavailable at the time a request ran. The action is enabled by default (`USAGE_PRICING_RECALCULATION_ENABLED`); on the usage view, choose **Recalculate**, then type `recalculate` to confirm. It is scoped to the selected date range, provider or model, and user path.

Recalculation reprices billed cost with the markup each row was billed at, and bills cache hits according to the current `bill_cache_hits`. Rows recorded before markups existed are billed at their provider cost. While markups are disabled, recalculation leaves billed cost unchanged.

<Warning>
  Recalculation **overwrites** the cost fields of every matching row, and
  **clears** the cost of any row whose model no longer resolves to pricing. The
  result reports how many rows still lack pricing. Token counts are never
  modified.
</Warning>
