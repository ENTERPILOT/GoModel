Azure OpenAI verwendet das Format der OpenAI-API mit zwei Unterschieden, die
GoModel übernimmt: einen `api-key`-Header statt `Authorization: Bearer` und
den Query-Parameter `api-version` bei Deployment-bezogenen URLs.

## Konfigurieren

```bash
AZURE_API_KEY=...
AZURE_BASE_URL=https://your-resource.openai.azure.com/openai/deployments/your-deployment
AZURE_API_VERSION=2024-10-21   # optional, Standardwert ist 2024-10-21
GOMODEL_MASTER_KEY=change-me
```

Oder in `config.yaml`:

```yaml
providers:
  azure:
    type: azure
    base_url: "${AZURE_BASE_URL}"
    api_key: "${AZURE_API_KEY}"
    api_version: "2024-10-21"
```

### Azure AI Foundry (v1-API)

Endpunkte von Azure AI Foundry wie
`https://proj1-resource.services.ai.azure.com/openai/v1/responses` verwenden die
unversionierte v1-API. Setzen Sie die Base-URL auf alles bis einschließlich `/openai/v1`:

```bash
AZURE_API_KEY=...
AZURE_BASE_URL=https://proj1-resource.services.ai.azure.com/openai/v1
```

Bei einer `/openai/v1`-Base-URL sendet GoModel standardmäßig kein
`api-version`, und das `model` im Request-Body wählt das Deployment, sodass ein
Provider alle Deployments der Ressource abdeckt. Lassen Sie `AZURE_API_VERSION`
(und `api_version` im YAML oben) leer; setzen Sie `preview` nur, um
Preview-Features zu aktivieren. Klassische
URLs `https://your-resource.openai.azure.com/openai/v1` funktionieren genauso.

`/openai/v1/models` listet die Modelle der Ressource, daher wird ein Deployment,
das wie sein Modell heißt (Standard in Foundry), direkt geroutet. Eigene
Deployment-Namen tragen Sie in `AZURE_MODELS` ein und setzen
`CONFIGURED_PROVIDER_MODELS_MODE=merge`.

## Prüfen

<CodeGroup>

```bash curl
curl -s http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [{"role": "user", "content": "Reply with the single word ok."}],
    "max_tokens": 80
  }'
```

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key=os.environ["GOMODEL_MASTER_KEY"],
)

completion = client.chat.completions.create(
    model="gpt-5",
    messages=[{"role": "user", "content": "Reply with the single word ok."}],
    max_tokens=80,
)

print(completion.choices[0].message.content)
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080/v1",
  apiKey: process.env.GOMODEL_MASTER_KEY,
});

const completion = await client.chat.completions.create({
  model: "gpt-5",
  messages: [{ role: "user", content: "Reply with the single word ok." }],
  max_tokens: 80,
});

console.log(completion.choices[0].message.content);
```

</CodeGroup>

`GET /v1/models` liefert die Deployments, die die Azure-Ressource bereitstellt,
mit `owned_by: "azure"`. Streaming, Responses, Embeddings und Batches
funktionieren genauso; Batches werden über den Ressourcenpfad
`/openai/batches` geroutet (`/openai/v1/batches` bei v1-Base-URLs).

## Mehrere Deployments

Jedes Azure-Deployment ist ein eigener Endpunkt. Registrieren Sie sie über
Umgebungsvariablen mit Suffix als separate Provider:

```bash
AZURE_GPT5_API_KEY=...
AZURE_GPT5_BASE_URL=https://your-resource.openai.azure.com/openai/deployments/gpt-5

AZURE_EMBED_API_KEY=...
AZURE_EMBED_BASE_URL=https://your-resource.openai.azure.com/openai/deployments/text-embedding-3-small
```

Dadurch werden `azure-gpt5` und `azure-embed` registriert. Um alle Deployments
einer Ressource über einen einzigen Provider bereitzustellen, verwenden Sie
stattdessen eine [v1-Base-URL](#azure-ai-foundry-v1-api).

## Hinweise

- GoModel akzeptiert die Deployment-bezogene URL, die Ihnen das Portal
  anzeigt. Für kontoweite Operationen (Auflisten von Modellen, Batches)
  entfernt GoModel das Suffix `/openai/deployments/<deployment>` automatisch,
  sodass eine einzige `AZURE_BASE_URL` sowohl Chat- als auch
  Ressourcen-Aufrufe abdeckt.
- `AZURE_API_VERSION` ist bei Deployment-bezogenen URLs standardmäßig
  `2024-10-21` und wird bei v1-URLs nicht gesendet. Setzen Sie es nur, wenn Sie
  eine andere stabile oder Preview-Version benötigen – zum Beispiel eine neuere
  Version der Responses API.

## Fehlerbehebung

- **`401 Unauthorized` / `403`** – `AZURE_API_KEY` passt nicht zu der
  Ressource, die das Deployment hostet, oder der Deployment-Name in der URL ist
  falsch.
- **`Resource not found` / `DeploymentNotFound`** – Das Modell im Request-Body
  muss der Deployment-Name sein, nicht das zugrunde liegende Basismodell.
- **`unsupported api version`** – Erhöhen Sie `AZURE_API_VERSION` auf eine
  Version, die das aufgerufene Feature unterstützt. Neuere Features der
  Responses API erfordern aktuelle Preview-Versionen. Lassen Sie es bei
  v1-Base-URLs leer oder verwenden Sie `preview`.
- **`404` bei Azure AI Foundry** – Die Base-URL muss auf `/openai/v1` enden,
  nicht auf dem vollständigen Endpunkt (`/openai/v1/responses`) oder der
  Projekt-URL (`/api/projects/...`).
