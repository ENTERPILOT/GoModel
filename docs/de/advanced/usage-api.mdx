## Übersicht

`GET /v1/usage` gibt den eigenen Verbrauch und die eigenen Limits des Aufrufers zurück – ohne
Admin-Zugriff. Ein einziger Aufruf beantwortet drei Fragen:

- Wie viel habe ich verbraucht (Requests, Token, geschätzte Kosten)?
- Wie viel Budget bleibt mir, und wann wird es zurückgesetzt?
- Welche Rate-Limits gelten für mich, und wie viel Spielraum bleibt?

Alles bezieht sich auf den effektiven [User Path](/de/features/user-path) des Aufrufers. Ein
Tool mit einem verwalteten API-Key – ein OpenCode-Plugin, eine CLI, ein Status-Widget – kann den
Endpunkt also mit dem Key abfragen, den es ohnehin für Inferenz verwendet. Das Abfragen verbraucht
kein Rate-Limit-Kontingent.

## Kurzes Beispiel

<CodeGroup>

```bash curl
curl http://localhost:8080/v1/usage \
  -H "Authorization: Bearer sk_gom_..."
```

```python Python
import httpx

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080", api_key="sk_gom_...")
usage = client.get("/v1/usage", cast_to=httpx.Response)

print(usage.json())
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: "sk_gom_...",
});

const usage = await client.get("/v1/usage");
console.log(usage);
```

## Wessen Nutzung Sie sehen

- **Verwalteter API-Key** – der an den Key gebundene `user_path` wird verwendet. Es sind keine
  Parameter nötig, und der Inhaber des Keys kann nichts außerhalb seines eigenen Teilbaums lesen.
- **Master-Key (oder Unsafe-Modus)** – übergeben Sie `X-GoModel-User-Path`, um einen Pfad
  auszuwählen, oder lassen Sie den Header weg, um `/` (alles) zu sehen:

<CodeGroup>

```bash curl
curl http://localhost:8080/v1/usage \
  -H "Authorization: Bearer $GOMODEL_MASTER_KEY" \
  -H "X-GoModel-User-Path: /team/alpha"
```

```python Python
import os

import httpx
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080",
    api_key=os.environ["GOMODEL_MASTER_KEY"],
    default_headers={"X-GoModel-User-Path": "/team/alpha"},
)
usage = client.get("/v1/usage", cast_to=httpx.Response)

print(usage.json())
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: process.env.GOMODEL_MASTER_KEY,
  defaultHeaders: { "X-GoModel-User-Path": "/team/alpha" },
});

const usage = await client.get("/v1/usage");
console.log(usage);
```

</CodeGroup>

## Response-Felder

### `usage`

Aggregiert aus erfassten Requests innerhalb des Datumsfensters, mit derselben Token- und
[Kostenschätzungs](/de/features/cost-tracking)-Semantik wie im Dashboard. Kostenfelder sind `null`,
wenn für keinen passenden Request Preise vorliegen. Der gesamte Block ist `null`, wenn kein
Storage-Backend die Nutzung aufzeichnet (`USAGE_ENABLED=false` oder keine Datenbank).

### `budgets`

Ein Eintrag pro [Budget](/de/features/budgets), das den Pfad abdeckt – einschließlich Budgets, die
von übergeordneten Pfaden wie `/` geerbt werden. `remaining` kann negativ werden und `usage_ratio`
über `1` steigen – beides bedeutet, dass das Budget überschritten ist. `exceeded` spiegelt die
Durchsetzung wider: Ist der Wert `true`, werden Requests bis `period_end` abgelehnt
(`period_seconds` mit dem Wert `2592000` ist der Sentinel-Wert für den Kalendermonat, nicht
buchstäblich 30 Tage). `resets_in_seconds` zählt relativ zu `server_time` bis `period_end`
herunter, sodass Sie den Wert anzeigen können, ohne sich um Uhrzeitabweichungen auf dem Client
kümmern zu müssen.

### `rate_limits`

Live-Zähler für jede User-Path-[Rate-Limit-Regel](/de/features/rate-limits), die den Pfad abdeckt.
`max_tokens`/`tokens_remaining`/`tokens_usage_ratio` erscheinen nur bei Regeln mit Token-Limits;
ein `period_label` mit dem Wert `concurrent` kennzeichnet eine Obergrenze für gleichzeitige
Requests, wobei `in_flight` die aktuelle Anzahl ist (und in `requests_usage_ratio` einfließt). Die
`*_usage_ratio`-Felder geben pro Dimension verbraucht/Limit an, ohne Begrenzung – Token-Fenster
können über `1` hinausschießen. `exhausted` ist `true`, wenn irgendeine Dimension vollständig
ausgeschöpft ist, und `resets_in_seconds` zählt relativ zu `server_time` bis `window_end` herunter
(entfällt bei Regeln für gleichzeitige Requests, die kein Fenster haben). Regeln mit Provider-
oder Modell-Scope werden nicht aufgeführt: Sie beschreiben gemeinsam genutzte
Infrastrukturkapazität, nicht den Aufrufer.

<Note>
  Rate-Limit-Zähler liegen pro Gateway-Instanz im Arbeitsspeicher: Sie werden bei einem Neustart
  zurückgesetzt, und bei N Replikaten führt jedes Replikat seine eigenen Zähler. Budgets sind die
  dauerhaften, instanzübergreifenden Werte.
</Note>

## Datumsfenster

Der `usage`-Block umfasst standardmäßig die letzten 30 Tage (Tagesgrenzen in UTC). Schränken Sie
ihn mit Query-Parametern ein – `days` oder explizit `start_date`/`end_date` (YYYY-MM-DD, maximal
365 Tage):

<CodeGroup>

```bash curl
curl "http://localhost:8080/v1/usage?days=7" \
  -H "Authorization: Bearer sk_gom_..."

curl "http://localhost:8080/v1/usage?start_date=2026-07-01&end_date=2026-07-07" \
  -H "Authorization: Bearer sk_gom_..."
```

```python Python
import httpx

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080", api_key="sk_gom_...")

last_seven_days = client.get("/v1/usage?days=7", cast_to=httpx.Response)
date_range = client.get(
    "/v1/usage?start_date=2026-07-01&end_date=2026-07-07",
    cast_to=httpx.Response,
)

print(last_seven_days.json())
print(date_range.json())
```

```javascript JavaScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:8080",
  apiKey: "sk_gom_...",
});

const lastSevenDays = await client.get("/v1/usage?days=7");
const dateRange = await client.get(
  "/v1/usage?start_date=2026-07-01&end_date=2026-07-07",
);

console.log(lastSevenDays);
console.log(dateRange);
```

</CodeGroup>

Budgets und Rate-Limits melden immer ihre eigenen aktuellen Zeiträume; das Fenster wirkt sich nur
auf `usage` aus.

## Cache-Modus

Der `usage`-Block zählt nur Requests, die an einen Provider gehen, damit er mit Budgets und Kosten
übereinstimmt. Treffer im [Response-Cache](/de/features/cache) werden ebenfalls erfasst, und
`cache_mode` macht sie sichtbar:

| Wert       | Zählt                                                    |
| ---------- | -------------------------------------------------------- |
| `uncached` | Nur Requests an Provider – der Standardwert              |
| `cached`   | Nur lokale Cache-Treffer – was der Cache kostenlos ausgeliefert hat |
| `all`      | Beides, Ihr gesamtes Request-Volumen                     |

```bash
curl "http://localhost:8080/v1/usage?cache_mode=cached" \
  -H "Authorization: Bearer sk_gom_..."
```

Ein Vergleich von `cached` mit dem Standardwert zeigt am schnellsten, welchen Anteil Ihres
Traffics der Cache abfängt. Nicht erkannte Werte fallen auf `uncached` zurück. `cache_mode` wirkt
sich nur auf `usage` aus: Budgets und Rate-Limits zählen nie Cache-Treffer, weil ein Treffer
nichts kostet und kein Kontingent verbraucht.

## Fehler

| Status | Bedeutung                                                              |
| ------ | ---------------------------------------------------------------------- |
| 400    | Fehlerhaftes `start_date`/`end_date`/`days`, umgekehrter Bereich, ein Bereich über 365 Tage oder ungültiger User Path |
| 401    | Fehlender oder ungültiger API-Key (wenn Authentifizierung konfiguriert ist) |
| 503    | Der Usage- oder Budget-Speicher konnte nicht gelesen werden (`usage_status_failed`) |
